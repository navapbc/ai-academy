# P6.4 — Accessibility pass (508/WCAG)

## Problem Frame

The AI Academy is an internal, government-adjacent training app, so **Section 508 / WCAG 2.1 AA** matters. Prior work (W2-9) added focus management, `aria-live`/`role="status"` regions, and `sr-only` correctness in spots (~114 usages), but there is **no automated a11y tooling**: no `jsx-a11y` eslint plugin and no axe/automated a11y tests. The goal is a full 508/WCAG audit — with the important caveat that automated tools catch only ~30–40% of WCAG; the rest requires human screen-reader/keyboard testing.

## Decisions (resolved in brainstorm)

- **Scope = full 508/WCAG audit, decomposed by what's automatable:**
  - **Automated (this task delivers):** add `jsx-a11y` eslint at **error** severity + fix all violations; add **axe** automated checks across key screens/components + fix all violations; produce a **WCAG 2.1 AA audit document** marking each criterion auto-verified / fixed / needs-manual.
  - **Manual (human follow-up — the autonomous pipeline cannot genuinely verify):** keyboard-only navigation walkthrough, real screen-reader testing (VoiceOver/NVDA), visual focus-indicator + color-contrast human judgment, and formal 508 sign-off. Enumerated in the audit doc.
- **jsx-a11y severity = error** (must-fix now): the build/CI fails on any violation, forcing all current violations fixed in this work and blocking new ones.
- Do **not** claim "508 certified" from the automated pass — that requires the human follow-up.

## Requirements

**Automated tooling + enforcement**
- R1. Add the `jsx-a11y` eslint plugin to the flat eslint config with rules at **error** severity; `npm run lint` fails on any a11y violation.
- R2. Fix **every** jsx-a11y violation the plugin surfaces across the codebase (no disables except a documented, justified few if truly unavoidable).
- R3. Add **automated axe** accessibility assertions covering the key surfaces (component-level via an axe matcher in the vitest/jsdom suite, and/or an `@axe-core/playwright` pass in e2e) with zero violations on covered surfaces.

**Audit artifact**
- R4. Produce `docs/accessibility/508-wcag-audit.md`: a WCAG 2.1 AA criterion checklist marking each as automated-pass / fixed-in-this-work / **needs-manual-verification**, plus the explicit manual checklist (keyboard walkthrough, SR testing, contrast/focus) for the human follow-up.

## Success Criteria
- `npm run lint` passes with `jsx-a11y` rules at error (zero violations).
- Automated axe checks pass with zero violations on the covered surfaces.
- The audit doc exists and clearly separates automated-verified items from the human follow-up list.
- No false claim of full 508 compliance — the manual portion is explicitly flagged as outstanding.

## Scope Boundaries
- **Manual SR/keyboard 508 verification is a documented human task** (the loop cannot verify assistive-tech UX) — not part of the merge's "done".
- Not a visual redesign; fixes are a11y-correctness (labels, roles, alt text, focus, contrast where mechanically detectable), not restyling.
- Contrast: fix what axe/tools flag; subjective/edge contrast calls are in the manual list.

## Key Decisions
- Full audit, but honestly split: automate + fix everything detectable now; hand off assistive-tech verification to a human. Matches W5-4 ("jsx-a11y lint + axe now, formal pass later") while honoring the "full audit" intent as far as automation allows.
- jsx-a11y at error to establish a hard regression floor.
