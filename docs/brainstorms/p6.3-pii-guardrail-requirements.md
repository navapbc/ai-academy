# P6.3 — Data-classification (PII) guardrail

## Problem Frame

Learners do hands-on labs that send their typed input to Claude (via the `chat`/`grade` Edge Functions). There is no reminder or guard against pasting **real client/constituent PII** into prompts. Because this is an AI-*literacy* app, data hygiene is part of the curriculum — so the guardrail's highest value is as a consistent **teaching moment**, not a brittle gate. Real PII (names, addresses) can't be reliably detected, so scanning/blocking would give false confidence and false-positive interruptions.

## Decisions (resolved in brainstorm)

- **Warn + allow (teach).** Surface a clear "don't paste real client PII" reminder at learner input surfaces; never block or delay a call.
- **Reminder only — no content scanning.** A standing, consistent notice near the input. No regex/heuristic PII detection, no acknowledgment gate.
- **Shared, reusable component.** Build the notice as one shared component so **P6.6** (submissions/reflections free of PII) can reuse it later. P6.3 places it at the pre-Claude-call input surfaces; P6.6 extends it to submission/reflection surfaces.
- Client-side teaching notice only (no Edge-Function enforcement — nothing to enforce without detection).

## Requirements

- R1. A single **shared, reusable PII-reminder notice** component with consistent, teaching-oriented copy ("don't paste real client/constituent PII; use fake/sample data") — branding-aware (uses the `injectBranding` placeholders where relevant).
- R2. The notice is surfaced at every learner **free-text input surface whose content is sent to Claude** — the hands-on Lab / prompt surfaces (e.g. the config-driven `Lab`, the Playground/PromptLab, and the free-text judge-graded exercises: critique, synthesis, voice-edit, prompt-eval, iteration). Always visible near the input; non-blocking.
- R3. The component is structured for reuse so **P6.6** can drop it onto submission/reflection surfaces without change.
- R4. Zero effect on the model-call path — purely presentational; no gating, no new network calls, no persistence.

## Success Criteria
- A learner sees a consistent PII reminder wherever they type input that will be sent to Claude.
- No model call is blocked, delayed, or altered.
- The notice is a single shared component (not copy-pasted per surface), ready for P6.6 reuse.

## Scope Boundaries
- No content scanning / PII detection (no regex for SSN/email/phone).
- No hard/soft blocking; no acknowledgment gate or persistence.
- No Edge-Function enforcement.
- P6.6 submission/reflection **enforcement** is a separate task (this only builds the shared notice + places it on the Claude-call surfaces).

## Key Decisions
- Teach over gate: aligns with the app's AI-literacy mission and avoids false confidence/false positives from unreliable PII detection.
- One shared component: consistency + P6.6 reuse, minimal carrying cost.
