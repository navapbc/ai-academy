# P4.3b — "Clean-critique" Labs (cells 2.2 & 2.3)

**Phase:** P4.3b — *A graded "critique the polished artifact" exercise on cells 2.2 and 2.3, scored by the existing P4.2 LLM-judge against a rubric, shown in place. Practice, not a gate.*
**Depends on:** P4.2 (the `grade` Edge Function + `requestLlmGrade`/`saveGrade`/`recordLabSubmission`), P3.6/P3.7 (the render-above-the-quiz exercise pattern).
**Date:** 2026-06-03
**Branch:** `feat/p4.3b-clean-critique`

## 1. Goal

Add a new interactive exercise — **Critique** — where the learner reads a polished,
realistic AI-generated artifact and writes a structured critique/validation of it. The
critique is graded by the **existing P4.2 LLM-judge** (`grade` Edge Function) against an
anchor rubric, and the anchor-scored result renders in place (reusing P4.2's result card).

This is **graded practice that records a `lab_submission` but does NOT gate completion**.
Cells 2.2 and 2.3 are `type:'content'` with an inline quiz; the **quiz stays the completion
gate** (same pattern as the P3.6/P3.7 exercises — render above the quiz, never call
`onComplete`).

Wired on two cells:
- **2.2 "Output validation as a verifiable skill"** — critique a polished AI *eligibility
  summary* whose authority is unverifiable from the artifact alone.
- **2.3 "Counteracting the polished-output trap"** — critique a slick *PRD* that reads
  "done" but silently decided an open question and states assumptions as facts.

**Out of scope:** champion-review UI/RLS (P5.1, unchanged); retrofitting other exercises;
matrix Stages 3–4; any change to the `chat` function, the quiz gate, or `parseVerdict`.

## 2. Context (current state)

- **The P4.2 judge** (`supabase/functions/grade/{verdict.ts,index.ts}`) is non-streaming,
  hardened (JWT authz, @navapbc.com domain, CORS allow-list, model allow-list, token clamp,
  per-user rate limit), and returns a validated JSON verdict. Its user message is built by
  `buildGradeUserMessage(rubric, submission)` where today
  `GradeSubmission = { brief; prompt; response }` and the template **hardcodes** the section
  headers `THE LEARNER'S PROMPT:` and `CLAUDE'S OUTPUT FROM THAT PROMPT:`. That framing does
  not fit a critique, where the two inputs are an *artifact under review* and the *learner's
  critique*.
- **The client grading path** (`src/lib/grading.ts requestLlmGrade`, `src/lib/progress.ts
  recordLabSubmission`→id + `saveGrade`) is reusable as-is; only the submission *shape*
  changes.
- **The exercise pattern** (`FailureSpotter`, `ReflectionCapture`, etc.): a self-contained
  component that renders an artifact via `ReactMarkdown + remarkGfm`, takes input, records a
  submission, and **does not accept `onComplete`** — completion is structurally the quiz's
  job. `ModuleRenderer.renderExercise()` dispatches on `module.labConfig.kind`; the inline
  quiz renders after and gates.
- **Lab.tsx's result card** (`#grade-result`, "Anchor-scored feedback … Provisional —
  pending review", per-anchor list) is the markup to reuse.
- **Content lives in two places:** lesson/quiz come from `curriculum-content.json` (seeded
  early); **lab configs come from migrations** (e.g. `…_seed_lab_config_2_1.sql`). Cells
  2.2/2.3 have body+quiz but **no `lab_config_json`** yet.

## 4. The judge generalization (D3) — back-compat is the hard constraint

`GradeSubmission` (in both `src/lib/grading.ts` and `supabase/functions/grade/verdict.ts`):

```ts
export interface GradeSection { label: string; text: string }
export interface GradeSubmission { brief: string; sections: GradeSection[] }
```

`buildGradeUserMessage` renders sections verbatim (no case transform):

```ts
export function buildGradeUserMessage(rubric: GradingRubric, submission: GradeSubmission): string {
  const anchors = rubric.anchors.map((a) => `- ${a.id} (${a.label}): ${a.description}`).join('\n');
  return [
    'RUBRIC ANCHORS:',
    anchors,
    '',
    'THE BRIEF THE LEARNER WAS GIVEN:',
    submission.brief,
    ...submission.sections.flatMap((s) => ['', `${s.label}:`, s.text]),
    '',
    'Score each anchor now as strict JSON.',
  ].join('\n');
}
```

**2.1 byte-equivalence:** the Lab call site passes
`sections: [{ label: "THE LEARNER'S PROMPT", text: prompt }, { label: "CLAUDE'S OUTPUT FROM THAT PROMPT", text: response }]`.
The rendered string is identical to today's hardcoded template — a new builder test asserts
this exactly (and the existing `parseVerdict` tests are untouched, since `parseVerdict` does
not change).

**Critique** passes
`sections: [{ label: 'Artifact under review', text: artifact.bodyMd }, { label: "The learner's critique", text: critique }]`,
with `brief: config.brief.instruction`.

Touched by this change: `verdict.ts` (type + builder), `grade/index.ts` (`isSubmission`
validates `{ brief, sections: {label,text}[] }`), `src/lib/grading.ts` (type), `Lab.tsx`
(call site). `GRADE_SYSTEM_PROMPT`, `parseVerdict`, the verdict result shape: unchanged.

> Authoring bar (`docs/content-guide.md`): no AI-isms; realistic civic-tech context;
> every factual claim grounded. **The provisions cited below are real and described

### 6.1 Cell 2.2 — polished AI "SNAP eligibility summary"

**Why this artifact (not the lesson's):** the 2.2 lesson already works through
`42 CFR 435.916` + "March 1, 2024." Reusing it would give away the answer. We use a
**different, real** provision: **7 CFR § 273.10**, *"Determining household eligibility and
benefit levels"* (SNAP) — distinct program/title/subject.

**Brief (instruction):** "An AI tool produced this eligibility summary for a caseworker to
forward. Write a short critique: which claims can you trust, which can't you verify from this
document alone, and what would you check before relying on it?"

**Artifact (markdown, reads senior-analyst-clean):** a SNAP eligibility summary that
correctly attributes determination to 7 CFR 273.10, includes **verifiable-in-principle**
case math (gross income vs. 130% FPL, standard + earned-income deduction), and plants:
1. a **specific effective date + dollar amount** for a standard-deduction change
   ("effective March 1, 2025, the standard deduction rose to $224"),
2. an unsourced **statistic** ("≈88% of eligible households in the state are enrolled") used
   to justify skipping outreach,
3. an authoritative-sounding **characterization of the cited regulation** presented as proof.

**Rubric anchors (4 × 0–2):**

| id | label | description (what a good critique catches) |
|----|-------|--------------------------------------------|
| `flag-citation-verify` | Verify the citation | Flags the cited regulation (7 CFR 273.10) / its characterization as something to confirm against the primary source, not trust because it's cited. |
| `flag-unverifiable-numbers` | Catch unverifiable claims | Identifies the specific effective date + deduction amount and the ~88% enrollment statistic as claims that cannot be verified from the artifact alone. |
| `distinguish-verifiable` | Don't blanket-reject | Distinguishes verifiable claims (the income/deduction math, household size) from unverifiable ones — critiques selectively rather than rejecting the whole summary. |
| `name-verification-step` | Name a concrete check | Names at least one concrete verification step — open eCFR for 7 CFR 273.10, check the deduction against the current USDA/FNS COLA figure, or request the source behind the 88%. |

**ANSWER KEY — planted issues, ground truth, sources:**

1. **Cited reg is real; trust the artifact's gloss only after checking.** 7 CFR § 273.10
   *"Determining household eligibility and benefit levels"* is a real SNAP provision
   governing how income, deductions, household size, and certification periods set the
   allotment. Source (cite): https://www.ecfr.gov/current/title-7/subtitle-B/chapter-II/subchapter-C/part-273/subpart-D/section-273.10
   (text verified via Cornell LII https://www.law.cornell.edu/cfr/text/7/273.10). *Planted
   problem:* the artifact's authoritative paraphrase is not itself proof — a good critique
   says "confirm the section actually says this."
2. **"Effective March 1, 2025, standard deduction → $224" — FABRICATED date+amount.** SNAP
   standard-deduction figures change via annual USDA/FNS COLA memos (Oct 1 fiscal-year
   cadence), not a March effective date, and the $224 figure here is invented for the
   exercise. Ground truth source for the real cadence/figures: USDA FNS SNAP COLA guidance
   (https://www.fns.usda.gov/snap/allotment/cola). *A good critique flags the date+amount as
   unverifiable from the artifact.*
3. **"≈88% of eligible households enrolled" — FABRICATED statistic, no source.** SNAP
   participation rates are estimated by USDA FNS and vary by state/year; no such figure is
   verifiable from this document. Source for where real rates come from: USDA FNS SNAP
   participation-rate reports (https://www.fns.usda.gov/snap/program-participation-rates).
   *Doubly bad because it's used to justify skipping outreach.*
4. **Verifiable-in-principle (do NOT reject):** the income-vs-130%-FPL test and deduction
   math are checkable against the case file + the current HHS poverty guidelines
   (https://aspe.hhs.gov/topics/poverty-economic-mobility/poverty-guidelines). A good
   critique keeps these and targets only the unverifiable claims.

**Framing grounded in NIST AI 600-1:** confabulation (colloquially "hallucination") is "a
natural result of the way generative models are designed," not a rare bug — so a fluent,
confident citation/number is exactly what you must verify. NIST AI 600-1 (July 2024), §2.2:
https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf (DOI 10.6028/NIST.AI.600-1).

### 6.2 Cell 2.3 — slick AI "PRD" for a benefits-renewal feature

**Why this artifact (not the lesson's):** the 2.3 lesson already works through a renewal PRD
that silently decided *partial submissions*. We keep the renewal-PRD frame but plant a
**different**, web-verified silently-decided question: **the ex parte (administrative)
renewal "reliable data" fallback.**

**Brief (instruction):** "An AI tool drafted this PRD and it reads ready to circulate. Write
a short critique: what open question did it silently decide, which statements are assumptions
dressed as facts, and what would you confirm with stakeholders before building?"

**Artifact (markdown PRD, confident, caveat-free — "Status: Ready for review · Confidence:
High"):** a "Quick Renew" Medicaid renewal feature that correctly references ex parte renewal
under 42 CFR 435.916, and plants:
1. **a silently-decided open question** — *what data counts as "reliable" to auto-renew (ex
   parte) vs. drop to the prepopulated form, and how the ambiguous/no-match case is handled.*
   The PRD states the happy path as settled and never decides the threshold;
2. **assumptions stated as facts** — "all enrollees receive a digital confirmation notice,"
   "every enrollee completes renewal in under 5 minutes," and a fabricated "internal data
   shows 95% complete renewal online → mail-in out of scope";
3. **false completeness** — no open questions, no caveats, "Ready for review / High
   confidence."

**Rubric anchors (4 × 0–2):**

| id | label | description |
|----|-------|-------------|
| `surface-open-question` | Surface the buried decision | Surfaces ≥1 silently-decided open question — e.g., what data counts as "reliable" to trigger ex parte renewal vs. the manual form, or how the no-match case is handled. |
| `separate-assumptions` | Assumptions ≠ facts | Separates stated assumptions from verified facts — flags "all enrollees get a digital notice," "under 5 minutes," and/or the 95%-online figure as assumptions/claims, not established facts. |
| `name-false-completeness` | Name the false "done" | Names the false sense of completeness — the confident, caveat-free framing hides unresolved decisions rather than resolving them. |
| `propose-stakeholder-confirm` | Confirm before building | Proposes what to confirm with stakeholders before acting — the reliable-data definition, the real digital-access rate, the non-digital/mail-in path, or authorized-representative submission. |

**ANSWER KEY — planted issues, ground truth, sources:**

1. **Ex parte renewal is real and correctly referenced; the "reliable data" threshold is the
   genuinely open question.** Under **42 CFR § 435.916(a)(1)**, the agency must redetermine
   eligibility *without requiring information from the individual* when it can do so based on
   reliable information available to it; (b) governs the prepopulated form when it cannot.
   *What sources/fields count as "reliable," and the no-match path, are real design decisions
   the PRD silently makes.* Sources: reg
   https://www.ecfr.gov/current/title-42/chapter-IV/subchapter-C/part-435/subpart-J/section-435.916
   ; CMS "Basic Requirements for Conducting Ex Parte Renewals"
   https://www.medicaid.gov/resources-for-states/downloads/ex-parte-renewal-slide-deck-12052024.pdf
2. **"All enrollees receive a digital confirmation notice" / "under 5 minutes" — assumptions
   as facts.** These exclude enrollees without reliable digital access and assert an untested
   performance target; an access/equity (and Section 508) concern, not a settled fact.
3. **"95% complete renewal online → mail-in out of scope" — FABRICATED statistic** presented
   as established internal data; unverifiable and used to justify dropping the non-digital
   path.

**Framing grounded in:** Anthropic AI Fluency Index (Feb 23 2026) — when output *looks*
finished, users question its reasoning less (≈−3.1 pp) and notice missing context less
(≈−5.2 pp): https://www.anthropic.com/research/AI-fluency-index (cite the percentage-point
figures, not the "5.6× less" phrasing, which is the *iteration* finding in secondary
coverage). Foundational: Mosier & Skitka, automation bias
(https://journals.sagepub.com/doi/10.1177/154193129604000413).
