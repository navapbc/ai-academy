# P4.1 — Generalize the Lab Component

**Phase:** P4.1 — *The MVP's 2.1 lab refactored into a config-driven `Lab` + `LabConfig` (all labs call Claude).*
**Depends on:** P2.3 (the 2.1 PromptLab), P3.2 (content-as-data / `lab_config_json`).
**Date:** 2026-06-02
**Branch:** `feat/p4.1-generalize-lab`

## 1. Goal

Refactor the bespoke 2.1 lab (`PromptLab`) into a reusable, config-driven `Lab`
component so later Stage-2 labs (P4.3–P4.8) can be added by extending
`LabConfig` rather than writing a new component each time. This is a **faithful,
minimal extraction**: the learner-facing behavior of cell 2.1 is unchanged; the
component is just de-hardcoded and renamed.

Out of scope: grading (auto-keys / LLM-as-judge / champion-review) is P4.2;
new lab types and prompt-assembly modes are P4.3+; splitting the `LabConfig`
union into "labs vs auto-graded exercises" (a larger refactor not required here).

## 2. Context (current state)

- **`src/components/PromptLab.tsx`** is the 2.1 lab: it reads
  `labConfig` (kind `'prompt-construction'`, from `modules.lab_config_json` via
  content-as-data), shows a brief (`task` + `constraints`) + collapsible scaffold
  hints + a constraint-derived self-check, lets the learner write a prompt and
  **Run** it against Claude (`streamChat`, with a model selector and streamed
  output), then **Save & complete** → `recordLabSubmission(user.id, { labId, transcript, status })`
  and `onComplete()`. Unlike the auto-graded exercises (classifier, sorter,
  failure-spotter, etc.), the lab **is** the cell's completion gate.
- **Hardcoded to 2.1:** `const LAB_ID = '2.1'` and the header strings "Lab:
  Prompt Construction" / "Write a constraint-first prompt and run it against
  Claude." Everything else already comes from config.
- **Wiring:** `ModuleRenderer.renderExercise()` switches on
  `module.labConfig?.kind`; `case 'prompt-construction'` renders `<PromptLab onComplete labConfig selectedPersona />`.
  Auto-graded exercises pass `labId={module.cellId}`; PromptLab does not (it uses
  the hardcoded id).
- **`PromptConstructionConfig`** (in `src/types.ts`, a `LabConfig` union member):
  `{ kind: 'prompt-construction'; brief: { task; constraints[] }; scaffoldHints: { label; hint }[] }`.
- **`recordLabSubmission(userId, { labId, transcript, status })`** inserts into
  `lab_submissions` (owner-only RLS); this is the seam P4.2's grading will build on.

## 3. Decisions

| # | Decision | Choice |
|---|----------|--------|
| D1 | Generalization scope | **Faithful minimal extraction.** Reproduce 2.1's flow exactly in a reusable `Lab`; defer richer frameworks to P4.3+. |

## 4. The generic `Lab` component (§1)

Rename `src/components/PromptLab.tsx` → `src/components/Lab.tsx`, refactored to a
config-driven Claude lab that preserves 2.1's exact flow and look:

- **`labId` from props** (passed `module.cellId`) replaces `const LAB_ID = '2.1'`.
- **Header from config**: `title` / `subtitle` (optional) with generic fallbacks
  (e.g. `title ?? 'Lab'`, `subtitle ?? 'Compose a prompt and run it against Claude.'`),
  replacing the hardcoded strings. Resolved via a small pure helper `labHeader(config)`.
- **Generic shell owns the reusable machinery:** model selector
  (`CLAUDE_MODELS`/`DEFAULT_MODEL_ID`), the prompt editor (with ⌘/Ctrl-Enter run),
  the run-against-Claude (`streamChat`) with streamed output and error/loading
  states, and **Save & complete** (`recordLabSubmission` + `onComplete` — the lab
  remains the completion gate).
- **Config supplies the lesson-specific parts**, all already present on
  `PromptConstructionConfig`: the brief (`task` + `constraints`), the collapsible
  scaffold hints, and the self-check list (derived from `constraints`).
- **`selectedPersona`** stays an accepted-but-unused optional prop (the
  construction lab is persona-agnostic), matching today.
- **Misconfig guard** retained: if `config?.kind !== 'prompt-construction'`,
  render the existing "Lab not configured" fallback.

No grading logic is added — that's P4.2.

## 5. Config type & wiring (§2)

**`src/types.ts`** — extend `PromptConstructionConfig` with two optional,
additive fields:

```ts
export interface PromptConstructionConfig {
  kind: 'prompt-construction';
  title?: string;      // lab header; generic fallback if absent
  subtitle?: string;   // lab subhead; generic fallback if absent
  brief: { task: string; constraints: string[] };
  scaffoldHints: { label: string; hint: string }[];
}
```

The `LabConfig` union is unchanged in membership.

**`src/components/ModuleRenderer.tsx`** — update the import (`PromptLab` → `Lab`)
and the case:

```tsx
case 'prompt-construction':
  return (
    <Lab
      config={module.labConfig}
      labId={module.cellId}
      onComplete={onComplete}
      selectedPersona={selectedPersona}
    />
  );
```

No other case changes; `renderInteractive`, the complete-button, and the
inline-quiz gate are untouched.

**Migration (`supabase/migrations/<ts>_lab_2_1_header.sql`)** — `jsonb_set` cell
2.1's `lab_config_json` to add `title='Prompt Construction'` and
`subtitle='Write a constraint-first prompt and run it against Claude.'`, so the
header reads exactly as today now that it's config-driven. Timestamped after the
latest migration; touches nothing else; targets the single `cell_id='2.1'` row.
