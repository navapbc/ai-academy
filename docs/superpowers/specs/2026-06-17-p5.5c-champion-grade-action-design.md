## Decisions (from the user, 2026-06-17)

- **Grade model: approve / return only.** A reviewer **Approves** (status →
  `reviewed`) or **Returns** with a note (status → `returned`, the note is feedback
  to the learner). **No score editing** — the LLM `rubric_scores` stays immutable as
  the machine record. (Settles the "override vs annotate" open question: neither —
  the champion's action is a decision + note, not a re-score.)
- **Write path: service_role Edge Function.** `lab_submissions` has no client-write
  RLS; the transition runs as service_role in a new `review-grade` function
  (mirroring P5.5a/P5.1a), authorized to **admin OR champion-of the submission's
  learner**. The service_role key stays server-side.

## Goal

Let a champion/admin act on a reviewable submission from the P5.5b queue: approve it
or return it with feedback, transitioning its status and recording who/when/note.

## Architecture

### Migration `20260617010000_lab_review_columns.sql`
Add to `lab_submissions` (idempotent `add column if not exists`):
- `review_note text` — champion feedback (esp. on return).
- `reviewed_by uuid references auth.users(id) on delete set null`.
- `reviewed_at timestamptz`.
No RLS change: existing P5.1c SELECT already exposes these to champion/admin; writes
stay service_role-only (no client write policy).

### Edge Function `supabase/functions/review-grade/`
- `review-grade-core.ts` (pure, node-tested): `parseReviewAction(body)` validating
  `{ submissionId: uuid, decision: 'reviewed'|'returned', note?: string (bounded) }`
  + the shared cors/ratelimit/allowlist/domain helpers (self-contained copies, same
  posture as admin-cohorts-core).
- `index.ts` (Deno): OPTIONS/CORS, POST-only, authn (signed-in @navapbc.com),
  rate-limit, parse, then:
  1. service_role read the submission (`id, user_id, status`); 404 if missing.
  2. **Authz**: admin (allowlist OR `profiles.role='admin'`) OR champion-of the
     submission's learner — replicating `is_champion_of` with a service_role query
     (`cohort_champions cc ⋈ enrollments e` where `cc.user_id = caller` and
     `e.user_id = submission.user_id`). Else 403.
  3. Update `lab_submissions` set `status = decision, review_note = note ?? null,
     reviewed_by = caller.id, reviewed_at = now()` for the id.
  - JSON `{ ok: true, decision }`.

### Client `src/lib/reviewGrade.ts`
`submitReviewDecision({ submissionId, decision, note })` — raw fetch with the
session token (mirrors `adminCohorts.invokeAdminCohorts`); `approveSubmission` /
`returnSubmission(note)` creators.

### UI — `ReviewQueue` detail (P5.5b) gains actions
A note textarea + **Approve** and **Return** buttons. Return requires a note
(feedback); approve note optional. On success the submission leaves the queue
(its status is no longer `reviewable`) → the detail closes back to the list, which
reloads. Busy/error states; read of the LLM verdict (GradeResultCard) unchanged.

## Testing

- **Unit** (`review-grade-core.test.ts`): `parseReviewAction` (valid decisions,
  uuid + note bounds, rejects unknown decision/non-object) + helpers.
- **Component** (`ReviewQueue.test.tsx` extension): Approve calls the wrapper with
  `reviewed`; Return requires a note then calls with `returned` + note; on success
  the list reloads (item gone); action error surfaces.
- **Gated integration** (`reviewGrade.integration.test.ts`): the service_role
  transition works (status → reviewed/returned + reviewed_by/at/note); an
  authenticated **client cannot** UPDATE `lab_submissions` (no write policy); a
  champion-of can act on their cohort's submission but the authz query rejects a
  cross-cohort one (assert the champion-of predicate at the DB level).
- **Served-function smoke**: champion approves/returns own-cohort submission → 200 +
  row updated; a champion acting on a cross-cohort submission → 403; non-champion
  learner → 403.

## Non-regression / conventions

- Additive: new function + client + migration (additive columns) + actions on the
  existing detail. No score mutation; LLM `rubric_scores` untouched. Pure logic split
  + zero `any` in src/. `P5.5c` ids in comments.
