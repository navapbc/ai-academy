# P5.3a — Learner self-view dashboard (own progress / scores / lab status)

**Item:** Phase 5 slice P5.3a (first slice of P5.3 Learner dashboard).
**Date:** 2026-06-17 · **Branch:** `feat/p5.3a-learner-dashboard`
**Depends:** P1.4 (data layer, merged). Per the Phase 5 build order P5.3a is the
"cheapest standalone — no new RLS" slice; it reuses existing owner RLS so it is
shippable early and independent of the staff dashboards.

## Goal

Give a learner a single place to see **their own** progress, quiz scores, and lab
submission statuses — the self-facing counterpart to the staff per-learner
drill-down (P5.2c). Today a learner sees only completion checkmarks in the sidebar;
quiz scores and lab statuses are surfaced nowhere learner-facing. This adds that
view. Out of scope: the calibration number + portfolio artifacts (that's P5.3b).

## Decisions

- **Reuse the P5.2c data-access, scoped to self.** `fetchLearnerDetail(userId)`
  already reads `modules` (published) + the learner's `module_progress`,
  `quiz_attempts`, `lab_submissions` via `.eq('user_id', userId)`. For a learner
  reading their **own** id, the existing **owner RLS** already permits every one of
  those reads — so the self-view needs **no new policy, view, or migration**. The
  pure shaping fns (`buildLearnerModuleRows`, `buildLearnerLabRows`) are reused
  verbatim. (Staff reuse the same fns under champion/admin RLS; learner reuse is the
  owner-RLS path of the identical query.)
- **Compute the summary cards locally — no dependency on the P5.2a aggregation
  views.** A new pure `summarizeOwnProgress(detail)` derives completion %, average
  best-quiz %, GLAT pass, and reviewable-lab count from the already-fetched detail.
  This keeps P5.3a independent of P5.2a (its DoD's "independent"), avoids the
  per-learner correlated-subquery cost flagged in P5.2a, and guarantees the cards
  are self-consistent with the table shown (both published-module-scoped).
- **Fresh read each time the view opens.** Unlike the always-mounted
  learning/playground/staff panes, the dashboard is **conditionally mounted** when
  the learner switches to it, so it fetches current data on open (reflecting any
  module just completed). A Retry affordance covers a failed read.
- **New top-level `View = 'progress'`, visible to everyone.** A "My progress"
  sidebar entry (no role gate — every learner gets it; staff see it too alongside
  the role-gated Staff entry). Reachability needs no `RoleGuard` (it's self data).
- **Share presentational primitives with the staff drill-down.** Extract the
  identical pieces (`StatCard`, `LabStatusBadge`, the stage-grouped module table,
  the lab list, `formatPct`, `STAGE_LABELS`) into `src/components/progress/
  ProgressPanels.tsx`; refactor the staff `LearnerDetail` to consume them with
  **byte-identical DOM** (its test suite guards the refactor). Avoids ~100 lines of
  duplication.

## Architecture

### `src/lib/learnerSelf.ts` — pure summary (no React, no network)

```ts
export interface OwnProgressSummary {
  completedCount: number;
  totalCount: number;       // published modules
  completionPct: number | null; // 0..1, null when no published modules
  avgQuizPct: number | null;    // mean best-quiz fraction over attempted modules
  glatPassed: boolean;          // 2.14 best attempt passed
  reviewableLabs: number;       // lab submissions with status 'reviewable'
}
export function summarizeOwnProgress(detail: LearnerDetailData): OwnProgressSummary
```

GLAT cell id is the canonical `'2.14'` (same constant P5.2a/P4.10 use), referenced
with a comment.

### `src/components/progress/ProgressPanels.tsx` — shared presentational

`formatPct`, `STAGE_LABELS`, `StatCard`, `LabStatusBadge`, `ModuleProgressTable`,
`LabSubmissionsList`. Pure presentational; no data-access.

### `src/components/LearnerDashboard.tsx` — the self-view

Reuses `useLearnerDetail(userId)` (rename of nothing — its doc comment is updated to
note both the staff and learner callers; behaviour unchanged) for fetch state, and
`summarizeOwnProgress` for the cards. Renders: header ("Your progress"), 4 summary
cards, the shared module table + lab list, plus loading / error+retry / empty
states. Learner-facing copy (no "awaiting review" wording implying staff action —
use "labs submitted for review").

### Wiring

- `src/types.ts`: `View = 'learning' | 'playground' | 'staff' | 'progress'`.
- `src/App.tsx`: conditionally mount `<LearnerDashboard userId={userId} />` for
  `view === 'progress'`; add the content-region aria-label case; arm focus on view
  change (existing `navIntentRef` path already handles `handleViewChange`).
- `src/components/layout/Sidebar.tsx`: a "My progress" button next to Learning,
  visible to all users.

## Completion / gating semantics

Read-only view. It records nothing, calls no `onComplete`, and does not affect
gating. (No graded-practice concern — there's no submission here.)

## Testing

- **Unit** (`learnerSelf.test.ts`): `summarizeOwnProgress` — completion fraction,
  avg over attempted only, GLAT pass via 2.14, reviewable count, empty/none cases.
- **Component** (`LearnerDashboard.test.tsx`, jsdom): mocks `fetchLearnerDetail`;
  asserts cards + a module row + a lab badge render, and the error→retry path.
- **Staff regression**: `staff/LearnerDetail.test.tsx` stays green after the
  presentational extraction (DOM identical).
- **E2E** (`e2e/16-learner-dashboard.spec.ts`): sign in as the seeded demo learner,
  click "My progress", assert the summary cards and at least one module row render.
  No Claude calls in this view (no stub needed).
- **db reset**: no migration added — confirm the suite/E2E run on a fresh reset.

## Non-regression / conventions

- Additive: new `View` member + new files; staff view refactor is DOM-identical.
- No new RLS/policy/migration; owner RLS only. Zero `any`. `P5.3a` ids in comments.
- No secret handling; client reads through the public anon key + RLS as elsewhere.
