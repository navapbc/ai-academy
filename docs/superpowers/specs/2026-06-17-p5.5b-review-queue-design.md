# P5.5b — Champion/admin review queue

**Item:** Phase 5 slice P5.5b (second slice of P5.5 Cohorts + review queue).
**Date:** 2026-06-17 · **Branch:** `feat/p5.5b-review-queue`
**Depends:** P5.1c (champion/admin SELECT on `lab_submissions`, merged), P5.2a (the
`reviewable_labs` count surfaced on the dashboard).

## Goal

Let a champion (admin: all cohorts) see the lab submissions awaiting review — the
judge-graded labs save `status='reviewable'` with an LLM `rubric_scores` verdict —
and open one to read the learner's submission + the anchor-scored feedback. Closes
the audit gap: "graded rows queue unreadably behind owner-only RLS." **Read-only**
this slice; the champion *grade action* (approve/override + status transition) is
P5.5c.

## Decisions

- **No new RLS/migration.** P5.1c already lets a champion read their cohort's
  `lab_submissions` and an admin all. A client `.from('lab_submissions')
  .select(...).eq('status','reviewable')` is therefore already cohort-scoped — the
  queue is a pure read layer over existing policies.
- **Reuse `GradeResultCard` for the verdict.** `rubric_scores` is stored as the
  exact `GradeResult` shape the card already renders ({perAnchor, overall,
  maxOverall, grader}) — pass it straight through.
- **Defensive transcript rendering.** `transcript` is per-lab `jsonb`; a pure
  `summarizeSubmission(transcript)` maps each known kind to labeled text blocks
  (the learner-authored artifact), with a JSON fallback for unknown shapes:
  - `voice-edit` → AI draft + learner revision
  - `iteration` → turn count + the learner's user-role messages
  - `prompt-eval` → the reusable prompt
  - `critique`/`synthesis` (the `noun` kind) → `transcript[kind]` text
  - 2.1 prompt-construction (`{brief,prompt,response}`, no kind) → prompt + Claude
    response
- **Champions and admins both see it** (champions are the primary reviewers); the
  RLS scopes content per role. In-page from `StaffArea`, mirroring the P5.2c/P5.5a
  drill-down (no new top-level `View`).

## Architecture

### `src/lib/reviewQueue.ts` — data-access + pure shaping
- Types: `ReviewQueueItem { submissionId, learnerUserId, learnerName, labId,
  transcript, rubricScores: GradeResult|null, grader, createdAt }`.
- `buildReviewQueue(submissions, profiles)` (pure): join names (full_name → email →
  short id, the `buildLearnerRoster` pattern), newest-first.
- `summarizeSubmission(transcript)` (pure): the labeled-text extractor above.
- `fetchReviewQueue()`: `lab_submissions.select('id,user_id,lab_id,transcript,
  rubric_scores,grader,created_at').eq('status','reviewable')` (RLS-scoped) +
  `profiles` name lookup for the surfaced ids → `buildReviewQueue`.

### `src/lib/useReviewQueue.ts` — fetch state (mirrors useLearnerDetail).

### `src/components/staff/ReviewQueue.tsx`
- List: one row per reviewable submission (learner, lab id, score `overall/max`,
  date) → click opens detail.
- Detail: learner + lab meta, the `summarizeSubmission` blocks, and
  `<GradeResultCard result={rubricScores} />` when present. Back to list / back to
  staff. Read-only (no grade action — P5.5c).
- Loading / error+retry / empty ("No submissions awaiting review").

### Wiring
`StaffArea`: replace the "Review queue" *Soon* tile with a live, clickable entry
(champion + admin) that opens `<ReviewQueue>` in-page (`showReviewQueue` state,
mirroring `showCohorts`).
