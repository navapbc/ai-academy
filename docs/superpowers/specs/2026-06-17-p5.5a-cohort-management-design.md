## Goal

Give admins a UI to manage the cohort substrate: create / rename / delete cohorts,
enroll / reassign / unenroll learners, and assign / unassign champions to cohorts.
This is the management surface over the P5.1b tables that the dashboards (P5.2)
already read from.

## Decisions

- **Writes via a service_role Edge Function (admin-only).** The P5.1b tables have
  **no client-write RLS** (writes are service_role-only by design). Mirroring P5.1a's
  `admin-set-role`, a new `admin-cohorts` Edge Function performs every mutation as
  service_role after verifying the caller is a signed-in **admin** (env
  `BOOTSTRAP_ADMIN_EMAILS` allowlist OR `profiles.role='admin'`). The client never
  writes these tables directly; the service_role key never reaches the browser.
- **Admin-only feature.** Cohort management (incl. assigning champions) is an admin
  action. Champions keep their read-only dashboard; the management UI is gated to
  `role==='admin'` (sidebar entry + `RoleGuard allow={['admin']}` + the function's
  own admin check — defence in depth).
- **Reassign = upsert on `enrollments.unique(user_id)`.** One cohort per learner is
  DB-enforced; enrolling a learner already in another cohort UPDATEs their row
  (`upsert onConflict: user_id`), not a second INSERT. Champion assignment upserts on
  `unique(cohort_id, user_id)` (idempotent).
- **One new admin read + an audit table (migration).** `cohort_champions` was
  owner-read only, so the admin UI can't list a cohort's champions — add an
  `is_admin()` SELECT policy. Add a locked-down `cohort_changes` audit table
  (mirrors `role_changes`); the function logs each mutation best-effort.
- **Champion assignment manages the champion *role*, not just the cohort link.**
  `profiles.role` gates staff access (P5.1d); `cohort_champions` scopes which
  learners a champion sees (P5.1c). They were independent, which made "assign a
  champion" a no-op for a learner (assigned but role unchanged → no staff access).
  So the function now ties them together: **assigning** a champion auto-grants
  `role='champion'` to a plain learner (admins/existing champions untouched);
  **unassigning** their **last** cohort demotes a champion back to `learner` (a
  champion of other cohorts keeps the role; an admin is never demoted). The role
  transition is decided by pure `roleAfterAssign`/`roleAfterUnassign` (unit-tested)
  and recorded in the `role_changes` audit. (Found in P5.5a human review.)
- **Action-dispatched request.** One endpoint, `{ action, ...fields }` discriminated
  union (`create_cohort`/`rename_cohort`/`delete_cohort`/`enroll_learner`/
  `unenroll_learner`/`assign_champion`/`unassign_champion`). Pure parse/validate in
  `admin-cohorts-core.ts` (node-testable); Deno glue in `index.ts`.

## Architecture

### Migration `20260617000000_cohort_management.sql`
- `is_admin()` SELECT policy on `cohort_champions` (admin enumeration).
- locked-down `cohort_changes` audit table (service_role writes only).

### Edge Function `supabase/functions/admin-cohorts/`
- `admin-cohorts-core.ts` (pure): `parseCohortAction(body) → {ok,value}|{ok:false,error}`
  validating each action's fields (uuid format, non-empty/trimmed name, length cap) +
  self-contained copies of `buildCorsHeaders` / `fixedWindowAllow` / `isAllowlistedAdmin`
  / `emailDomainAllowed` (Edge Functions bundle independently — same posture as
  admin-core).
- `index.ts` (Deno): OPTIONS/CORS, POST-only, authn (signed-in @navapbc.com),
  rate-limit, admin authz (allowlist OR profiles.role), parse, dispatch each action
  to the matching service_role write, best-effort audit insert, JSON `{ok:true,...}`.
  Mirrors `admin-set-role` line-for-line in structure.

### Client `src/lib/adminCohorts.ts`
- `invokeAdminCohorts(action)` — raw `fetch` to `/functions/v1/admin-cohorts` with the
  session Bearer token; throws `Error(body.error)` on non-2xx. Typed creators:
  `createCohort` / `renameCohort` / `deleteCohort` / `enrollLearner` /
  `unenrollLearner` / `assignChampion` / `unassignChampion`.
- Reads (admin RLS): `fetchCohortManagement()` reads `cohorts`, `profiles`
  (id/full_name/email/role), `enrollments`, `cohort_champions` and folds them via a
  pure `buildCohortManagement(...)` into `{ cohorts: [{id,name,members[],champions[]}],
  users: [...], unassignedUsers: [...] }` for the UI's lists + pickers.

### UI `src/components/staff/CohortManagement.tsx` (admin-only)
- Create-cohort form; per-cohort card: rename, delete, members list (unenroll),
  enroll-a-learner picker, champions list (unassign), assign-champion picker.
- Calls the wrapper; reloads `fetchCohortManagement` on success; surfaces errors;
  optimistic-free (reload after each write keeps it simple and correct).
- Reached in-page from `StaffArea` (admin sees a clickable "Cohort management" card;
  champions don't), mirroring the P5.2c `LearnerDetail` drill-down (no new `View`).

## Testing

- **Unit** `admin-cohorts-core.test.ts`: `parseCohortAction` per action (valid +
  rejects), uuid/name validation, the copied helpers (cors/ratelimit/allowlist).
- **Unit** `adminCohorts.test.ts`: pure `buildCohortManagement` (members/champions
  grouping, unassigned-users derivation, name resolution).
- **Gated integration** `adminCohorts.integration.test.ts` (RUN_DB_TESTS + live
  stack + service key): the **service_role write path** works for create/enroll/
  reassign(unique user_id)/assign; an **anon/authenticated client write is BLOCKED**
  by RLS (no write policy); the new admin **read** on `cohort_champions` works while
  a plain learner cannot read others'. Mirrors `adminRole.integration.test.ts`.
- **Component** `CohortManagement.test.tsx`: mock the wrapper + reads; create/enroll/
  assign call the right action; error surfaces; reload on success.
- **Manual smoke**: `supabase functions serve` + invoke `admin-cohorts` as the
  seeded admin → create a cohort, enroll the demo learner, assign a champion; verify
  rows + an audit row; confirm a non-admin call is 403.

## Non-regression / conventions

- Additive: new function, new client lib, new component, one migration (additive
  policy + new table). No change to existing tables' columns or the dashboards.
- Edge Function key handling matches P5.1a (service_role server-side only; never in
  the browser). Zero `any` in production source. `P5.5a` ids in comments.
