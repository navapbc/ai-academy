# P4.8 — Use-case library + 4D Diligence Statement (cell 2.11)

**Item:** Phase 4 P4.8 (remediation W4-3) — the portfolio instrument for cell 2.11. Additive: a new
`LabConfig` kind + component + dispatch + seed. No schema, no change to existing labs.
**Date:** 2026-06-09
**Branch:** `feat/p4.8-use-case-portfolio`

## What 2.11 is (from the loaded lesson, migration `20260602190000`)
- A **personal AI use-case library**: a running record of where AI clearly helps, where it doesn't,
  the prompts that worked, and the failure modes hit. The lesson stresses the "didn't help" entries
  save the most time — a library of only wins is a tell.
- A **Diligence Statement**: a ~250–400 word write-up for ONE high-stakes use case across Anthropic's
  4D AI Fluency — **Delegation** (what you handed the model), **Description** (how you framed the
  task), **Discernment** (how you evaluated the output), **Diligence** (disclosure, validation,
  attribution). `evidenceType='portfolio'`, dimensions Delegation+Diligence, `selfReportValidity:high`.

## Instrument (additive, mirrors `ReflectionCapture`'s ungraded-capture shape)
A new `use-case-portfolio` lab kind. Cell 2.11 is a `content` module with an inline quiz (the
completion gate), so this is **graded PRACTICE that records a `lab_submissions` row and never calls
`onComplete`** — structurally enforced by the component taking only `{config, labId}`. It is an exit
artifact, **not LLM-graded** (the artifact is the evidence; self-report validity is high, like the
reflection capture) — captured, with a completeness gate, not scored.

Two parts in one card:
1. **Use-case library builder** — add/remove entries; each entry is a verdict (**Helps** / **Doesn't
   help**), a short task, the prompt/approach, and the failure-mode/what-to-watch. Submit requires
   `minEntries` complete entries **including at least one "Doesn't help"** (encodes the lesson's
   honesty point).
2. **4D Diligence Statement** — one labelled textarea per dimension (from config, in order), with a
   combined soft word target and a hard floor to submit.

On submit: `recordLabSubmission(user.id, { labId, transcript: { kind:'use-case-portfolio', entries,
statement, helpsCount, doesntCount, wordCount }, status:'submitted' })`, then a saved confirmation.
A `role="status"` readiness line lists what's still needed (sr-announced), matching the a11y bar set
in W2-9.

## Pure core (testable, no React): `useCasePortfolio.ready.ts`
`evaluatePortfolioReadiness(state, config) -> { ready, reasons[] }` — completeEntries ≥ minEntries,
≥1 complete "Doesn't help" entry, every dimension field non-empty, combined statement words ≥
`minWords`. Returns human reasons for the readiness line and drives the disabled Submit.

## Config (content-as-data) — `UseCasePortfolioConfig`
Carries `intro`, the library section copy + `minEntries` + field placeholders, and the diligence
section copy + the 4 `dimensions` ({id,label,prompt}) + `targetWords`/`minWords`. Seeded for 2.11
via an idempotent `update … set lab_config_json … where cell_id='2.11' and lab_config_json is null`
migration at `status='in_review'` (body_md/quiz_json untouched — the lesson + quiz gate stay intact).

## Out of scope
Cross-session portfolio read-back/accumulation (entries are built in-session and snapshotted into the
submission; a champion-visible running portfolio is a P5 follow-up), LLM grading, any
completion-semantics change, P4.9/P4.10. The legacy `UseCaseLib` (`type:'use-case'`, currently
unused by the curriculum — audit D-29) is left untouched; this is a new instrument, not an in-place
edit of it.
