# P5.2b — Staff cohort dashboard (shell + cohort filter + summary cards)

**Item:** Phase 5 slice P5.2b (second slice of P5.2 Live dashboard).
**Date:** 2026-06-15 · **Branch:** `feat/p5.2b-dashboard-shell`
**Depends:** P5.2a aggregation layer (merged, #77), P5.1d role-aware client (merged,
#76). Per the Phase 5 build order, P5.2b is the next slice after the aggregation
layer it reads from.

## Goal

The first UI on top of the P5.2a aggregation views: a staff-only cohort dashboard
showing completion %, GLAT pass rate, average quiz score, labs-awaiting-review, and
a score distribution — **by cohort**. Reachability is already gated to admins and
champions by the P5.1d `RoleGuard`; the data boundary is the P5.1c/P5.2a RLS (a
champion sees only their cohort, an admin sees all, a learner sees nothing here).
This slice adds no new policy or view — it only consumes them.

## Decisions (from brainstorming)

- **Dashboard is the staff landing.** `StaffArea` stops being a placeholder: it
  renders the cohort dashboard at the top and keeps the **Review queue** and
  **Cohort management** "Soon · P5.5" tiles below it. No internal tab/route layer
  yet — those features are separate slices.
- **Per-cohort, filter narrows to one.** The views return one row per cohort, so we
  render straight from them: "All cohorts" (default) stacks one block per visible
  cohort; the filter narrows the display to a single cohort. **No blended-average
  math** — sidesteps the learner-weighting trap and matches "by cohort" in the DoD.
- **Client-side filter, no realtime.** The scoped views already return every cohort
  the caller can see in one fetch, so the cohort filter is pure client-side state —
  no refetch per selection. Realtime/polling is P5.2d.

## Architecture

Mirrors the established `progress.ts` (pure async data-access) / `useProgress.ts`
(React hook) split.

### `src/lib/dashboard.ts` — pure async data-access

No React, no localStorage. Reads the PostgREST-exposed views, maps rows to typed
shapes, throws on error. RLS scopes every read to the caller.

```ts
export interface CohortSummary {
  cohortId: string;
  cohortName: string;
  learnerCount: number;
  avgCompletionPct: number | null;   // 0..1
  glatPassRate: number | null;       // 0..1 — 0 until P4.10 ships
  avgQuizPct: number | null;         // 0..1
  reviewableTotal: number;           // integer count
}

export type ScoreBand = 'lt60' | '60to79' | '80to100';
export interface ScoreDistribution {
  lt60: number;
  '60to79': number;
  '80to100': number;
}
```

- **`fetchCohortSummaries(): Promise<CohortSummary[]>`** — reads
  `cohort_progress_summary`; **drops the `NULL`-`cohort_id` group** (unenrolled
  learners — the view collapses them into one NULL row; the spec for P5.2a says the
  dashboard filters to real cohort ids). For the surviving cohort ids, reads
  `cohorts (id, name)` to attach names. Returns sorted by `cohortName`.
  - *Name lookup is keyed on the ids the scoped view returned*, so a champion never
    queries names for cohorts they can't see. (The `cohorts` table is readable by
    any authenticated user, so we must not enumerate it — we look up only the ids the
    RLS-scoped summary already surfaced.)
- **`fetchScoreDistribution(): Promise<Map<string, ScoreDistribution>>`** — reads
  `cohort_score_distribution`, pivots the `(cohort_id, band, learner_count)` rows
  into a per-cohort `{lt60, '60to79', '80to100'}` (missing bands → 0).

### `src/lib/useDashboard.ts` — React hook

Owns `{ summaries: CohortSummary[], distribution: Map<string, ScoreDistribution>,
loading: boolean, error: string | null, reload: () => void }`. Fetches both reads in
parallel once on mount (`Promise.all`); `reload` re-runs them for the error-retry
affordance. Uses the cancelled-flag pattern from `useRole` so a unmount mid-fetch
can't set state. No caching (staff data is not the learner-progress cache; a fresh
read per visit is correct and cheap).

### `src/components/staff/CohortDashboard.tsx` — the view

Consumes `useDashboard`. Owns the client-side cohort filter (`'all' | cohortId`,
default `'all'`).

1. **Cohort filter** — a labeled `<select>` with an "All cohorts" option plus one
   option per `summaries` entry (by name). Rendered whenever ≥1 cohort is visible.
2. **Per-cohort blocks** — `'all'` renders every summary; otherwise the one selected.
   Each block:
   - Header: cohort name + learner count.
   - **4 summary cards** straight from the row: Avg completion %
     (`avgCompletionPct`), GLAT pass rate (`glatPassRate`) with a small "0% until the
     GLAT ships (P4.10)" footnote, Avg quiz score (`avgQuizPct`), Labs awaiting review
     (`reviewableTotal`).
   - **Score distribution** — a labeled horizontal segmented bar over the three bands
     (`<60` / `60–79` / `80–100`) with per-band counts, from the distribution map.
     "No quiz data yet" when the cohort has zero banded learners.
3. A shared `formatPct(n: number | null)` renders `—` for null, else
   `${Math.round(n * 100)}%`.

### `src/components/StaffArea.tsx` — staff landing

Renders `<CohortDashboard />` at the top; keeps the Review queue + Cohort management
"Soon · P5.5" tiles below (the P5.2 dashboard tile is removed — it's now live). The
existing role-aware header ("Admin area" / "Champion area") stays.

## States

`RoleGuard` (P5.1d) already handles reachability — only admins/champions mount this.
Inside the dashboard:

- **Loading** — spinner with `role="status"` + sr-only label (sibling parity with
  `RoleGuard` / `App`).
- **Error** — `role="alert"` notice + a Retry button calling `reload()`.
- **Empty** — "No cohorts assigned to you yet" when the scoped fetch returns zero
  cohorts. This is the *expected* state for a champion with no cohort assignment and
  on a fresh DB with no enrollments — not an error.

## Accessibility

- Filter `<select>` has an associated `<label>`.
- Cards convey value in text (not color alone); the distribution bar segments carry
  text labels + counts, not color-only encoding (D-20 lesson).
- Loading/error use `role="status"` / `role="alert"` to match the rest of the app.

## Testing

- **`src/components/staff/CohortDashboard.test.tsx`** (jsdom) — mocks `useDashboard`
  and asserts:
  - renders one block per cohort under "All cohorts";
  - the filter narrows the display to a single cohort;
  - summary cards show the formatted values (incl. `—` for null pct);
  - the distribution bar renders band counts;
  - loading, error (+retry calls `reload`), and empty states render.
- **`src/lib/dashboard.test.ts`** (node) — optional small unit test for the
  distribution pivot + the NULL-cohort drop, if pure logic is worth isolating;
  otherwise covered via the component test's mock.
- **No new DB test.** P5.2a's gated `dashboardAggregation.integration.test.ts`
  already proves the RLS boundary these views inherit; this slice adds no policy or
  view. (Re-stating the boundary in a UI test would duplicate, not strengthen.)

## Out of scope

- Per-learner drill-down (P5.2c).
- Realtime subscription / polling (P5.2d).
- Review queue, cohort CRUD (P5.5).
- E2E coverage — exercising the staff view needs a champion/admin-seeded session;
  defer to P5.2c or a W6 E2E pass rather than bundle a heavy harness change here.
- Any change to the P5.2a views or RLS policies.
