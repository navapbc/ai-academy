# P4.5a — "Context-window diagnostic" Lab (cell 2.5)

**Phase:** P4.5a — *An auto-graded, single-select diagnostic on cell 2.5 ("Working with the context window"). The learner reads realistic civic-tech AI-session scenarios and, for each, picks the best diagnosis/remedy; auto-graded with a per-item "why" and a keepable quick-reference takeaway. Practice, not a gate.*
**Depends on:** P3.8 (#— the `ScenarioExercise` component + the `disclosure-builder`/`regulatory-check` `kind`s it already serves), P4.1 (the `lab_config_json` content-as-data lab pipeline), P3.6/P3.7 (the render-above-the-quiz exercise pattern).
**Date:** 2026-06-03
**Branch:** `feat/p4.5a-context-diagnostic`

## 1. Goal

Add an auto-graded diagnostic exercise to cell 2.5 ("Working with the context window") that drills
the lesson's core idea: **the context window is the model's working memory** (everything it can read
at once — your prompt, the pasted material, the conversation so far — measured in tokens at roughly
1.5 per word). When a session outgrows the window the model **drifts**: it contradicts a rule it
stated correctly earlier, or it loses pasted material. The remedies the lesson teaches:

- **Start a fresh thread** when old context has drifted and the model is contradicting itself.
- **Re-state / re-paste the authoritative rule or constraint** near the current turn.
- **Paste only the relevant section**, not a whole manual — irrelevant context degrades answers too,
  not just overflow.
- **Don't keep one marathon thread** for every task; a new thread per task keeps the window clean.

The learner reads ~5 realistic civic-tech AI-session scenarios (SNAP, Medicaid, public housing) and,
for each, picks the best diagnosis/remedy. It auto-grades against a seeded `correctIndex`, shows a
per-item "why," and compiles the correct calls into a keepable **"Working with the context window —
quick reference"** takeaway.

This is **auto-graded practice that records a `lab_submission` but does NOT gate completion.** Cell
2.5 is `type:'content'` with a 3-question inline quiz; the **quiz stays the completion gate** (same
pattern as the #48 critique, #49 output-audit, #50 calibration, #51 synthesis, #52 voice-edit —
render above the quiz, never call `onComplete`).

**Out of scope:** any new component (this reuses `ScenarioExercise`); the grading engine / LLM judge
(this is deterministic single-select, no LLM); the quiz gate; champion-review UI/RLS (P5.1); any
change to cells 1.9/1.10 (`disclosure-builder`/`regulatory-check`) — they must stay byte-stable and
their tests green.

## 2. Reuse decision — NO new component

This diagnostic is the **same single-select-scenario shape** the existing `ScenarioExercise` already
serves for 1.9 (`disclosure-builder`) and 1.10 (`regulatory-check`): a list of `{ prompt,
options[4], correctIndex, why }` items + a `takeaway` panel that, after grading, compiles the correct
option text of every item into a keepable cheat-sheet. `ScenarioExercise`:

- already renders the items, grades against `correctIndex`, reveals the per-item `why`, shows the
  `score / maxScore`, and records a `lab_submissions` row via `recordLabSubmission` with **no
  `onComplete`** (it is structurally not a gate);
- already compiles the takeaway from `items[i].options[items[i].correctIndex]`.

So this phase is **purely additive content + one new `kind` on an existing union**, with **no
behavioral change** to the component:

| Decision | Choice |
|----------|--------|
| New component vs. reuse `ScenarioExercise` | **Reuse.** The shape is identical; the only thing that varies between the three `kind`s is seeded content + the intro-card copy (`KIND_COPY`). Building a new component would duplicate the grade/takeaway/record logic for no gain. |
| Rename `ScenarioExerciseConfig` to something generic? | **No rename.** The interface name is already generic ("scenario exercise"), and a rename would churn 1.9/1.10's type imports + tests for zero benefit. We only **extend the `kind` union** (`'disclosure-builder' \| 'regulatory-check' \| 'context-diagnostic'`). |
| Component edit | **One additive line:** add a `'context-diagnostic'` entry to `ScenarioExercise`'s `KIND_COPY` record (it is typed `Record<ScenarioExerciseConfig['kind'], …>`, so extending the union *requires* the new entry — the compiler enforces it). The two existing entries are untouched, so 1.9/1.10 render byte-for-byte the same. |
| Completion semantics | **Practice, not a gate.** `ScenarioExercise` takes no `onComplete`; the inline quiz stays the gate. Records a `lab_submissions` row (`transcript: { answers, score, maxScore }`, `status:'submitted'`). |
| Seed | One migration `20260603050000_seed_lab_config_2_5.sql` (timestamp after #52's `20260603040000`), `where cell_id='2.5' and lab_config_json is null`, `status='in_review'`, `version=version+1`, `updated_at=now()`. Idempotent across `db reset`. |

## 4. Content — the scenarios, the answer key, the takeaway (conceptual; `status:'in_review'`)

> **Authoring bar (`docs/content-guide.md`):** no AI-isms; realistic civic-tech context
> (benefits / Medicaid / SNAP / housing), consistent with the existing cells. **Factual risk is
> low** — these are conceptual best-practices grounded in the 2.5 lesson + the IBM context-window
> framing (the model's working memory, ~1.5 tokens/word, irrelevant context degrades answers, restart
> when it drifts). The scenarios deliberately use **different specifics** from the 2.5 lesson's worked
> example (a Medicaid renewal that flips annual→monthly) **and from the inline quiz** (a 40-min
> contradiction, an 80-page manual, a marathon thread), so the lab reinforces the concepts without
> handing the learner the quiz answers verbatim. Token figures are illustrative round numbers used to
> build intuition, marked as "about."

Five single-select items. Correct-answer positions are varied (1, 2, 3, 0, 2) so the answer key
isn't a fixed column.

### Item 1 — contradiction after a long session → fresh thread + re-paste the authoritative rule
**Prompt:** "You've spent about 40 minutes refining a SNAP denial notice with an AI tool. Earlier in the thread it correctly said the household has 90 days to appeal. Now, deep in the same conversation, it says 30 days. What's the best move?"
**Options:**
0. "The model got worse over time — switch to a different AI tool and start the work there."
1. **"Start a fresh thread and re-paste the authoritative appeal-window rule, then continue."** ✅
2. "Stay in the thread and point out the mistake — it'll self-correct from here."
3. "Paste the full 200-page SNAP policy manual into the thread to remind it of every rule."
**correctIndex: 1**
**Why:** "The correct 90-day appeal window scrolled out of the context window as the thread grew — the model didn't degrade, and it won't reliably self-correct a fact it can no longer see. A fresh thread with just the authoritative rule and the current draft brings the fact back into working memory. Pasting the whole manual floods the window with material the task doesn't need and buries the rule that matters."

### Item 2 — one narrow question → paste only the relevant section, not the whole manual
**Prompt:** "A caseworker needs one narrow answer: does a specific Medicaid waiver cover non-emergency medical transport? They're about to paste the entire 300-page waiver handbook so the model 'has everything.' What's the better move?"
**Options:**
0. "Paste the whole handbook — more context always makes the answer more accurate."
1. "Paste nothing and let the model answer the waiver question from general knowledge."
2. **"Paste only the transport-coverage section the question is actually about."** ✅
3. "Split the handbook across ten messages so the whole thing still fits in the thread."
**correctIndex: 2**
**Why:** "The window has hard limits, and irrelevant material doesn't just risk overflow — it pulls the answer off target. Pasting only the transport-coverage section gives the model exactly what the question needs. Answering from general knowledge invites a confident but unsourced guess about a specific waiver, and splitting the handbook across messages still floods the window with pages the question never touches."

### Item 3 — marathon thread → a new thread per task
**Prompt:** "A teammate keeps a single AI thread open all week — eligibility questions, a grant narrative, meeting notes, code snippets, all in one conversation — because they think 'the model remembers more that way.' What would you tell them?"
**Options:**
0. "They're right — one long thread is always sharper because the model retains everything."
1. "It doesn't matter — thread length has no effect on answer quality either way."
2. "Just tell the model to ignore the earlier topics and keep using the one thread."
3. **"Start a new thread for each task — unrelated history piles up in the window and pulls answers off course."** ✅
**correctIndex: 3**
**Why:** "A week of unrelated topics fills the window with stale context that crowds out the current task and causes drift — more history isn't more accuracy. A fresh thread per task keeps only what's relevant in view. Telling the model to 'ignore' the earlier topics doesn't reclaim the space: that text still sits in the window competing for attention."

### Item 4 — early rule now ignored, keep the thread → re-state the constraint near the current turn
**Prompt:** "In a long thread drafting a public-housing waitlist letter, you set a firm rule early on: never tell applicants their spot is guaranteed. Forty messages later the latest draft promises a guaranteed unit. You'd rather not lose this thread. What's the most reliable fix?"
**Options:**
0. **"Re-state the 'never promise a guaranteed spot' rule in your next message, right before asking for the revision."** ✅
1. "Trust that the rule you set early in the thread still holds and just ask for small edits."
2. "Scroll up, find your original instruction, and click it — that re-activates the rule."
3. "Conclude the model can't follow rules and write the whole letter by hand instead."
**correctIndex: 0**
**Why:** "The early instruction has drifted far from the current turn and lost its grip — that's why the draft now contradicts it. Re-stating the constraint in your next message puts it back in the model's immediate working memory. Scrolling to the old message changes nothing: what governs the answer is what you send now, not what's visible on your screen — and abandoning AI entirely overcorrects for a context problem you can fix in one line."

### Item 5 — token-budget intuition (~1.5 tokens/word)
**Prompt:** "A context window holds about 8,000 tokens, and text runs about 1.5 tokens per word. Roughly how much of that budget does a single 2,000-word policy excerpt consume?"
**Options:**
0. "About 300 tokens — a tiny fraction, so length rarely matters."
1. "About 2,000 tokens — one token per word."
2. **"About 3,000 tokens — nearly 40% of the window, so paste excerpts, not whole manuals."** ✅
3. "None — pasted documents don't count against the budget, only your typed prompt does."
**correctIndex: 2**
**Why:** "At about 1.5 tokens per word, 2,000 words is roughly 3,000 tokens — nearly 40% of an 8,000-token window from one excerpt. Pasted material counts against the budget exactly like your prompt and the running conversation do, which is why a 'paste everything' habit fills the window fast. A rough token sense tells you to bring in the section you need, not the whole manual."

### Takeaway — "Working with the context window — quick reference"
`takeaway.title`: **"Working with the context window — quick reference"**
`takeaway.intro`: "The context window is the model's working memory — your prompt, what you paste, and the conversation so far, at roughly 1.5 tokens per word. When it overflows or fills with clutter, answers drift and contradict facts the model got right earlier. Keep these moves handy:"

(The component compiles the correct option text of each item into the bullet list, so the
quick-reference reads: re-paste the authoritative rule in a fresh thread · paste only the relevant
section · a new thread per task · re-state the key constraint near the current turn · a rough token
sense → paste excerpts, not manuals.)

**Framing grounded in the lesson's own sources** (no new external claims): the context window is the
model's working memory measured in tokens at ~1.5/word; anything outside it "effectively doesn't
exist for the model"; most "the AI gave me a weird answer" moments are context-management failures;
irrelevant context degrades answers, not just overflow; the fix when it drifts is to summarize what
matters into a clean new prompt and restart. (Lesson 2.5 "Working with the context window"; IBM,
*What is a context window?*)
