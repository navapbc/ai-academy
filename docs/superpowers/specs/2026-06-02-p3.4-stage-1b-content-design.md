## 4. Content plan (§1)

Each cell gets a Nava-voiced, civic-tech-grounded lesson (concrete scenarios in
the style of 1.4) plus a 4-question scored MC quiz (~24 questions total).

- **1.1 — Mechanical mental model of how LLMs work** (Discernment): next-token
  prediction, tokens, training vs. inference, "pattern completion, not retrieval
  or understanding," probabilistic output/temperature, the context window. Sets
  up 1.2 and calibrated trust.
- **1.2 — Hallucination as a structural feature, not a bug** (Discernment): why
  fabrication is intrinsic to next-token prediction, confident-wrong output,
  where it bites in benefits/legal/policy work, mitigations (grounding,
  verification, citing sources).
- **1.7 — AI bias, fairness, and accessibility blind spots** (Discernment):
  training-data bias, disparate impact on benefit populations, accessibility
  (plain language, non-English speakers, screen readers), Nava's equity mandate.
- **1.8 — Energy, environmental, and sovereignty conversation** (Diligence):
  compute/energy/water cost of training and inference, data sovereignty and where
  government data physically lives, honest framing for civic work.
- **1.11 — Honest framing of job-shape change** (Delegation): augmentation vs.
  wholesale replacement, task-shape change, non-hype framing for civic-tech roles.
- **1.12 — Civic-tech-specific AI harm patterns** (Discernment + Diligence):
  wrongful benefit denials, automation bias in casework, opacity and appeal
  rights, exclusion — real patterns and how to spot them.

**Quiz conventions:** objects match the `QuizQuestion` type the app already
parses — `question`, `options[]`, `correctIndex` (in range), `explanation`.
Distractors are plausible; explanations teach, not just confirm.

**Matrix-evidence note:** the matrix assigns richer primary evidence
(reflection/performance-task) to 1.7, 1.8, 1.11, 1.12. For P3.4 every cell still
gets a knowledge-check MC quiz to meet the "lessons + quizzes" DoD; deeper
evidence types are later work.

## 5. Migration mechanics (§2)

One new migration, timestamped after the content-as-data one:
`supabase/migrations/<ts>_stage_1b_content.sql`. For each of the six cells:

```sql
update public.modules set
  body_md    = $md$<authored lesson markdown>$md$,
  quiz_json  = $json$[ ...4 questions... ]$json$::jsonb,
  status     = 'in_review',
  version    = version + 1,
  updated_at = now()
where cell_id = '1.1';
```

- **Replay-safe:** on `supabase db reset`, the seed inserts the stub, then this
  migration overwrites it. `where cell_id = …` targets exactly one row;
  re-running is harmless.
- **Badge auto-clears:** once `body_md` no longer contains `*Coming soon.*`,
  `isModuleLive()` returns true and the nav drops the "Soon" badge — no code
  change.
- **No schema, code, or component changes.** RLS, the `modules` SELECT policy,
  and the quiz render path (P3.2.3a) already handle DB-sourced quizzes.
- **Sign-off follow-up:** when an SME approves, a trivial migration flips these
  rows from `'in_review'` to `'published'`.

## 6. Testing & verification (§3)

Data-only change, so verification centers on the migration applying cleanly and
the content rendering through the real app.

- **Migration replay:** `npx supabase db reset` applies all migrations cleanly
  (catches SQL/heredoc/JSON errors). Then a DB check that each of the six
  `cell_id`s has non-stub `body_md`, a `quiz_json` array of 4 questions, and
  `status = 'in_review'`.
- **`quiz_json` validity:** each question has `question`, `options[]`,
  `correctIndex` within `options` range, and `explanation` — validated in the
  reset check.
- **Lint/build:** `npm run lint` and `npm run build` stay green.
- **In-app (Playwright, the P1.4/P3.2 verification style):** signed in as the
  demo user, for each cell confirm the real lesson renders (no "Coming soon"),
  the "Soon" badge is gone in the nav, the quiz runs, and a passing attempt
  records to `quiz_attempts` and marks the cell complete. Capture one lesson and
  one quiz-result screenshot as evidence.
- **Existing suites** (`progressCache`, `resolveCurrentModuleId`, skip-if-no-stack
  `progress` integration) remain green — unaffected.

No new unit tests: there is no new function to test; the content is data and the
render path was tested in P3.2.
