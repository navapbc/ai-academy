# P3.5 — Interactive: Scenario-Sorter (cell 1.3)

**Phase:** P3.5 — *8-scenario delegate/assist/human-only/refuse sorter + key + rationale.*
**Depends on:** P3.2 (content-as-data — merged).
**Date:** 2026-06-02
**Branch:** `feat/p3.5-scenario-sorter`

## 1. Goal

Build the academy's scenario-sorter interactive for matrix cell **1.3**
("Recognizing when AI is appropriate vs. when human judgment is essential"). The
learner sorts eight civic-tech scenarios into four categories — **delegate /
assist / human-only / refuse** — then sees an answer key with a rationale for
each. The sorter is cell 1.3's interactive and completion gate, replacing its
current MC quiz.

Scenario content is **drafted by Claude for later SME review** (rows marked
`status='in_review'`), as in P3.4.

Out of scope: other cells, other interactives (P3.6), a sorter-specific attempts
table, drag-and-drop.

## 2. Context (current state)

- **Content-as-data is live.** Modules are read from `public.modules` at runtime
  (`fetchCurriculum` in `src/lib/modules.ts`) and grouped into `Phase[]`.
  `ModuleRenderer` renders `module.content` (lesson) then dispatches an
  interactive by `module.type`.
- **Interactive precedent:** `ModuleRenderer.renderInteractive()` switches on
  `type` → `PrivacySimulator` (`simulator`), `PromptLab` (`lab`, reads
  `module.labConfig` from the DB `lab_config_json` column — the content-as-data
  pattern this work mirrors), `Quiz` (`quiz`), `UseCaseLib` (`use-case`),
  `Glossary` (`glossary`). The standalone "I've completed this section" button
  renders only for `content`/`glossary`, so interactive types gate completion
  through their own `onComplete`.
- **Cell 1.3 today:** `type='content'` with an authored lesson (`body_md`) and a
  3-question delegation MC quiz (`quiz_json`, added in PR #22). The sorter
  assesses the same skill more richly.
- **Quiz/inline-quiz behavior:** a non-`quiz` module with `module.quiz` renders
  an inline quiz as its completion gate. Clearing 1.3's `quiz_json` removes that.
- **Tested layer:** the repo unit-tests pure lib logic with Vitest
  (`progressCache`, `resolveCurrentModuleId`, mapping); React components are
  verified via Playwright, not unit tests.

## 3. Decisions

| # | Decision | Choice |
|---|----------|--------|
| D1 | Where scenario data lives | **In the DB.** New additive `sorter_config_json` jsonb column on `public.modules`, mirroring `lab_config_json`. SME-editable, no rebuild. |
| D2 | Relationship to 1.3's quiz | **Sorter replaces the quiz.** Cell 1.3 = lesson + sorter; set `type='sorter'` and `quiz_json=NULL`. |
| D3 | Interaction model | **Click-to-assign** (four category buttons per scenario), keyboard/screen-reader accessible; no drag-and-drop, no new dependency. |
| D4 | Completion gate | All eight correct → `onComplete()` (mirrors the quiz's 100% rule), with a "Try again" loop; rationales stay visible after first check. |
| D5 | Attempt persistence | None. Completion recorded via the existing `module_progress` path through `onComplete`; no sorter attempts table, not written to `quiz_attempts`. |
| D6 | Content authoring | Claude drafts the 8 scenarios + rationales; rows marked `status='in_review'` for SME review. |

## 4. Data model & schema (§1)

- **Migration A (schema):** add nullable `sorter_config_json jsonb` to
  `public.modules` (additive; no backfill, no FK). RLS unchanged (the existing
  authenticated-SELECT policy covers the new column).
- **Migration B (content):** for cell 1.3 —
  `update public.modules set type='sorter', sorter_config_json=$json$…$json$::jsonb, quiz_json=NULL, status='in_review', version=version+1, updated_at=now() where cell_id='1.3';`
  (`body_md` lesson unchanged). Replay-safe (`where cell_id` targets one row).
- **Types (`src/types.ts`):**
  - add `'sorter'` to `ModuleType`;
  - `SorterCategory = 'delegate' | 'assist' | 'human-only' | 'refuse'`;
  - `SorterScenario { id: string; text: string; correct: SorterCategory; rationale: string }`;
  - `SorterConfig { kind: 'scenario-sort'; intro?: string; scenarios: SorterScenario[] }`;
  - `Module` gains `sorterConfig?: SorterConfig`.
- **Mapping (`src/lib/modules.ts`):** add `sorter_config_json` to
  `MODULE_COLUMNS` and `ModuleRow`; map `sorter_config_json ?? undefined` →
  `sorterConfig` in `mapRowToModule` (same pattern as `labConfig`).

## 5. Component & wiring (§2)

**`src/components/ScenarioSorter.tsx`** — `ScenarioSorter({ config, onComplete })`,
styled to match existing cards (white, `nava-mint` border, `rounded-3xl`):

1. **Intro + legend** — short prompt plus a one-line definition of each of the
   four categories.
2. **Eight scenario rows** — each shows scenario text and a segmented control of
   four real `<button>`s (delegate / assist / human-only / refuse) with
   `aria-pressed`; selected state highlighted (`nava-green`). State:
   `Record<scenarioId, SorterCategory>`.
3. **Check answers** — button disabled until all eight assigned; on click, grade
   locally.
4. **Reveal: key + rationale** — each row shows correct/incorrect, the correct
   category, and its rationale; a "n / 8 correct" score line.
5. **Completion** — all eight correct → "Continue" calls `onComplete()`. Else a
   "Try again" lets the learner change wrong picks and re-check; rationales stay
   visible.

**Grading helper:** pure `gradeScenarios(assignments, scenarios)` →
`{ correctIds: string[]; total: number; allCorrect: boolean }`, extracted from
the component so it is unit-testable without React.

**`ModuleRenderer` wiring:** add
`case 'sorter': return <ScenarioSorter config={module.sorterConfig} onComplete={onComplete} />;`.
No change to the standalone complete-button logic (already excludes non-`content`
types). With 1.3's `quiz_json` cleared, no inline quiz renders alongside.

**Empty-config guard:** if `sorterConfig` is missing/empty, render nothing (the
lesson still shows) — same defensive posture as the other interactives.

## 6. Scenario content (§3)

**Four-category rubric** (shown as a legend; basis for the key):
- **Delegate** — AI end-to-end: low-stakes, easily verifiable, no sensitive data.
- **Assist** — AI helps; a person directs, checks, and owns the result.
- **Human-only** — a person must make and own the call (AI may help prep, never decide).
- **Refuse** — don't bring AI into this at all: prohibited data class or
  unauthorized use (ties to 1.4 / 1.5).

**Eight scenarios, two per category** (civic-tech-grounded, matching 1.3's
lesson). Full text + rationales authored in the implementation plan:

1. Delegate — reformat an already-published public FAQ into a bulleted cheat-sheet.
2. Delegate — generate alt-text for decorative icons in an internal slide deck.
3. Assist — draft a first version of a plain-language benefits explainer you'll fact-check and edit.
4. Assist — brainstorm user-research interview questions for caseworkers.
5. Human-only — decide whether a specific family qualifies for benefits today.
6. Human-only — write the message informing an applicant their benefits are denied.
7. Refuse — paste a beneficiary's full case file (name, SSN, health notes) into a personal ChatGPT account.
8. Refuse — use an unapproved AI tool to auto-generate final eligibility determinations with no human in the loop.

Intentional teaching tension sits at the two hard boundaries: **delegate vs.
assist** (how much human ownership a task needs) and **human-only vs. refuse** (a
human must *decide* vs. AI shouldn't be involved at all). Each scenario gets a
one-to-two-sentence rationale in the key.

## 7. Testing & verification (§4)

- **Unit (Vitest, pure logic):**
  - `gradeScenarios` — all-correct → `allCorrect: true`; a wrong pick flagged and
    `allCorrect: false`; partial assignment handled.
  - `mapRowToModule` — a row with `sorter_config_json` maps to `sorterConfig`; a
    null maps to `undefined`.
- **Migration replay:** `npx supabase db reset` applies cleanly. DB checks: cell
  1.3 has `type='sorter'`, `sorter_config_json` array length **8**, `quiz_json`
  **null**, `status='in_review'`; every scenario's `correct` is one of the four
  valid categories.
- **Lint/build:** `npm run lint` clean; `npm run build` succeeds (Node 22).
- **In-app (Playwright, demo user):** open 1.3 → lesson + sorter (no MC quiz);
  assign all eight correctly → Check → key + rationale reveal, "8 / 8",
  "Continue" completes the module. Probe: one wrong pick → "n/8" + "Try again"
  works, rationales stay visible. Screenshot the graded state.
- **Existing suites** (`progressCache`, `resolveCurrentModuleId`,
  skip-if-no-stack `progress`) stay green.
