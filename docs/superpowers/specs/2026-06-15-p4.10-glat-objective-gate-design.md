# P4.10 — GLAT objective gate (cell 2.14)

**Item:** Phase 4 task P4.10 (the final Stage-2 instrument; cell 2.14).
**Date:** 2026-06-15 · **Branch:** `feat/p4.10-glat-objective-gate` (to be created)
**Depends:** P3.3/P3.4 (Stage 1 content) + P4.11 (Stage 2 lessons/quizzes) — all loaded. The
question bank is supplied: `docs/content/glat-question-bank.md`.

## Goal

Replace cell 2.14's placeholder 4-question quiz with the **GLAT** — an objective,
auto-graded exam drawn from a fixed bank, where **≥80% on the scored set** sets the
program **completion marker** ("passed the course"). Per **D7** this is an **exit
credential only**: it unlocks nothing and adds **no Stage 3** (no `stage='3'` schema).

## Decisions (D7 + brainstorming)

- **Dedicated `glat` exercise kind** — an additive `LabConfig` union member + a `glat`
  dispatch case, parallel to every other P4.x instrument (keeps parallel PRs merging
  cleanly). Not an extension of the standard `Quiz` (which passes only at 100% —
  `Quiz.tsx:67` — and has no Section-A / exit-credential semantics).
- **Pass recorded as a passing `quiz_attempts` row on module 2.14** — **zero new
  schema.** The P5.2a `learner_progress_summary` view and the P5.2b dashboard already
  compute GLAT-pass as `exists(quiz_attempts where module_id='2.14' and passed)`, so
  this lights them up automatically. Multiple attempts are already supported (best
  score wins).
- **Section A (5 self-report items) is captured but not scored** — stored in the same
  attempt record, excluded from the pass computation (the bank specifies this).
- **All 35 scored items, every attempt, fixed bank order (B then C)** — simplest and
  fair for an exit credential; no randomized draw (YAGNI).
- **The GLAT gates 2.14; the existing 4-question quiz is removed** — the 35-item bank
  supersedes it; two assessments on one cell would be redundant. The GLAT lab gates the
  cell (calls `onComplete` on pass), following the cell-2.1 / D8 "lab gates" precedent.
- **Retake allowed freely** — each attempt is recorded; the best attempt is the pass
  signal (the lesson explicitly teaches "restudy and retake").

## The bank

`docs/content/glat-question-bank.md` (supplied by Nava):

- **Section A** — 5 soft/self-report items (A1–A5), 5-point scales, **diagnostic, not
  scored**.
- **Section B** — 20 objective questions (B1–B20). Each: question, 0-based options, one
  correct (`correctIndex`), a `Why:` rationale. Some are True/False (2 options).
- **Section C** — 15 supplemental objective questions (C1–C15), same shape.
- **Scored set = B + C = 35 items.** Gate = **≥80% ⇒ ≥28/35 correct.**

## Architecture

### 1. Content-as-data — seed the bank into `modules.lab_config_json` (2.14)

A seed migration authors the bank into the 2.14 row's `lab_config_json` as a `glat`
config and **clears the 4-question `quiz_json`** for 2.14. Editing the row edits the
exam, no rebuild — the established content-as-data pattern.

> **Transcription is accuracy-critical.** All 35 `correctIndex` values come from the
> `✓`-marked option in the markdown; rationales from the `Why:` line. A wrong
> `correctIndex` is a wrong gate. The plan isolates transcription as its own careful,
> verified step (cross-check count = 35 scored + 5 diagnostic; spot-check several
> against the doc).

### 2. Types — `GlatConfig` (`src/types.ts`)

New additive `LabConfig` union member:

```ts
interface GlatScaleItem {       // Section A — diagnostic, unscored
  id: string;                   // 'A1'..'A5'
  prompt: string;
  scaleLabels?: [string, string]; // optional low/high anchors for the 5-point scale
}
interface GlatScoredItem {      // Sections B + C — scored
  id: string;                   // 'B1'..'B20', 'C1'..'C15'
  question: string;
  options: string[];            // 2..4 options (True/False allowed)
  correctIndex: number;         // 0-based
  rationale: string;
}
interface GlatConfig {
  kind: 'glat';
  passThreshold: number;        // 0.8 (explicit for transparency)
  sectionA: GlatScaleItem[];
  sectionBC: GlatScoredItem[];
}
```

### 3. Pure scoring — `scoreGlat` (`src/lib/grading/scoreGlat.ts`)

No LLM. Pure and unit-tested:

```ts
interface GlatResponses {
  sectionA: Record<string, number>;   // itemId -> 1..5 (may be partial)
  sectionBC: Record<string, number>;  // itemId -> selected option index
}
interface GlatResult {
  correct: number;
  total: number;                       // = sectionBC.length (35)
  pct: number;                         // correct / total (0..1)
  passed: boolean;                     // pct >= passThreshold
  perItem: { id: string; selected: number | null; correctIndex: number; isCorrect: boolean }[];
}
function scoreGlat(config: GlatConfig, responses: GlatResponses): GlatResult;
```

Section A is passed through untouched (never read by the scorer). Unanswered scored
items count as incorrect.

### 4. Component — `GlatExam.tsx` (`src/components/exercises/`)

Consumes the `glat` config + the standard lab props (the cell's module + `onComplete`).

- Renders **Section A** (5 labelled scales) then the **35 B+C questions** (radio groups).
- **Submit** → `scoreGlat` → results view: a pass/fail banner, `correct/35 (NN%)`, and
  per-question correct/incorrect with the bank's rationale; Section A acknowledged as
  captured (not scored). Submit is enabled once all scored items are answered (Section A
  optional — diagnostic).
- **On pass:** record a `quiz_attempts` row via the existing `recordQuizAttempt` path —
  `moduleId='2.14'`, `score=correct`, `maxScore=35`, `passed=true`,
  `answers` = the namespaced map (`A1..A5` 1–5 values + `B*`/`C*` selected indices) — then
  call `onComplete` (the lab gates 2.14).
- **On fail:** record the attempt with `passed=false` (no `onComplete`); show results + a
  **Retake** button that resets the form.
- a11y to sibling-lab parity: `role="status"`/`role="alert"` where the others use them,
  radios in labelled `fieldset`/`legend` groups, correctness conveyed in text (not color
  alone — the D-20 lesson).

### 5. Dispatch + gating — `ModuleRenderer.tsx`

Add a `case 'glat'` rendering `<GlatExam>` (additive). Configure 2.14 so the **lab
gates** (no quiz present), reusing the existing cell-2.1 "lab gates" wiring; confirm the
renderer completes 2.14 only via the GLAT's `onComplete`.

## Data flow

`GlatExam` → `scoreGlat` (pure) → on pass `recordQuizAttempt({moduleId:'2.14', score,
maxScore:35, passed:true, answers})` + `onComplete` → Supabase `quiz_attempts` row →
P5.2a view `glat_passed=true` → P5.2b dashboard GLAT-pass-rate reflects it. No new table,
no new RLS (owner-only `quiz_attempts` already exists).

## Testing

- **`scoreGlat` unit tests** — the 80% boundary (27/35 fail, 28/35 pass), Section A
  excluded from scoring, all-correct (35/35 pass), all-wrong (0/35 fail), unanswered =
  incorrect.
- **`GlatExam` component test** (jsdom) — render → answer scored items → submit → pass
  records a `quiz_attempts` row (mock the record path) + calls `onComplete`; a failing
  set shows results + Retake and does **not** call `onComplete`; Section A values are
  included in the recorded `answers` but never change pass/fail.
- **`ModuleRenderer` dispatch test** — a `glat` config renders `GlatExam`; other kinds
  unaffected.
- **Seed idempotency** — re-running the migration upserts (no duplicate), 2.14
  `quiz_json` is cleared, `lab_config_json` holds 35 scored + 5 diagnostic items.
- **E2E deferred** — consistent with recent slices (would need a Stage-2-unlocked seeded
  session). Noted, not built.

> **Node 22** required for jsdom component tests (`ERR_REQUIRE_ESM` on Node 20) — prefix
> test runs with `nvm use 22`.

## Out of scope

- Any Stage 3 representation (D7 — none exists, none added).
- Realtime, champion review (GLAT is objective auto-graded — no `lab_submissions`,
  nothing `reviewable`).
- A dedicated "course completed" badge/surface in the learner or staff UI (the pass
  signal exists in `quiz_attempts`; surfacing it is a later slice if wanted — e.g. P5.3b).
- Changing the `passThreshold` semantics or the GLAT-pass derivation in the P5.2a view.
