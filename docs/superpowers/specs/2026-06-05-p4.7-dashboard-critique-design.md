# P4.7 — Lab: Dashboard-Critique (cell 2.13)

**Phase:** P4.7 — *Productivity-illusion critique: a dashboard-critique exercise where the learner names the rework/quality signals a speed-only dashboard hides.*
**Depends on:** P4.1 (the generalized lab pattern). Not P4.2 — scoring is deterministic, not LLM-judged.
**Date:** 2026-06-05
**Branch:** `feat/p4.7-productivity-critique`

## 1. Goal

Build the dashboard-critique exercise for cell 2.13 ("Resisting metric and
productivity illusions"). The learner is shown one realistic **speed-only
productivity dashboard** and a checklist of candidate dimensions. They mark which
signals the dashboard **hides**. The app **auto-grades** the selection against an
answer key — reporting which hidden quality/rework signals they correctly named,
which they missed, and which visible metrics they wrongly flagged (false
positives) — and records the result as a lab submission.

This makes cell 2.13's lesson concrete: a speed metric quietly drops quality,
rework, and downstream cost, and the literate move is to name what a single
number hides.

Out of scope: LLM-as-judge grading (P4.7 is a *computed*, deterministic score,
not an anchor score); gating completion (2.13's inline quiz remains the gate);
other cells.

  `lab_submissions` (owner-only RLS) and returns the new row id. Existing

- **Naming check:** no `dashboard-critique` / `DashboardCritique` /

## 4. Config type + scoring computation (§1)

**`src/types.ts`** — new union member:

```ts
export interface DashboardCritiqueConfig {
  kind: 'dashboard-critique';
  intro?: string;
  /** The speed-only productivity dashboard under review. */
  dashboard: {
    title: string;
    metrics: { label: string; value: string; trend?: string }[]; // visible cards, e.g. {label:"Drafts/day", value:"12", trend:"▲30%"}
  };
  /**
   * Candidate dimensions. `hidden:true` = a quality/rework signal the dashboard
   * OMITS (the answer key — learner SHOULD flag as missing). `hidden:false` = a
   * decoy already visible on the dashboard (learner should NOT flag).
   */
  signals: { id: string; label: string; hidden: boolean; why: string }[];
}
```

Added to `export type LabConfig = … | DashboardCritiqueConfig;` (additive, last).

**Pure helper `src/components/exercises/dashboardCritique.score.ts`:**

```ts
export interface DashboardCritiqueInput {
  selectedIds: string[];                       // signal ids the learner marked MISSING
  signals: { id: string; hidden: boolean }[];
}
export interface DashboardCritiqueResult {
  correct: string[];     // hidden signals correctly flagged (true positives)
  missed: string[];      // hidden signals NOT flagged (false negatives)
  falseFlags: string[];  // visible decoys wrongly flagged (false positives)
  hiddenTotal: number;   // count of hidden signals in the config
  namedCount: number;    // correct.length
}
export function scoreDashboardCritique(input: DashboardCritiqueInput): DashboardCritiqueResult;
```

- Build a `Set` from `selectedIds`. For each signal:
  - `hidden && selected` → `correct`
  - `hidden && !selected` → `missed`
  - `!hidden && selected` → `falseFlags`
  - `!hidden && !selected` → ignored (correctly left unflagged)
- `hiddenTotal = signals.filter(s => s.hidden).length`; `namedCount = correct.length`.
- Order within each bucket follows config order (stable, testable).
- No divide-by-zero / no throws: empty selection → all hidden ids in `missed`,
  `falseFlags` empty; unknown ids in `selectedIds` (not in `signals`) are ignored.
- Unit-tested.

## 5. Component + wiring (§2)

**`src/components/exercises/DashboardCritique.tsx`** — `{ config, labId }`,
OutputAudit/FailureSpotter card style, a small phase state machine (select →
reveal):

1. **Intro + dashboard** — `config.intro`, then `config.dashboard` rendered as
   metric cards (label / value / optional trend). The dashboard reads as a
   convincing speed-only readout.
2. **Checklist** — "Which signals does this dashboard hide? (select all that
   apply)" with one checkbox per `signal.label` (ALL signals listed — decoys
   included — in config order). A "Check my answer" submit button.
3. **Reveal** — `scoreDashboardCritique({ selectedIds, signals: config.signals })`;
   show **"You named N of M hidden signals."** plus per-signal feedback with each
   signal's `why`:
   - ✓ **correct** — hidden, you named it
   - ✗ **missed** — hidden, you didn't name it
   - ⚠ **false flag** — visible on the dashboard, not a missing signal
   Then `recordLabSubmission(user.id, { labId, transcript: { kind: 'dashboard-critique', selectedIds, correct, missed, falseFlags, hiddenTotal, namedCount }, status: 'submitted' })`.
   A "Start over" resets to the checklist. **No `onComplete`.**

`if (!user)` guard + non-blocking save error (inline message, never blocks the
reveal), like the other exercises. No Claude call anywhere.

**`ModuleRenderer` wiring** — add to `renderExercise()` + import:

```tsx
case 'dashboard-critique':
  return <DashboardCritique config={module.labConfig} labId={module.cellId} />;
```

No `onComplete`; no other case changes.

## 6. Seed content (§3)

A migration seeds 2.13's `lab_config_json` with the `dashboard-critique` config
(`status='in_review'`), leaving its lesson + quiz intact. Content is the lesson's
own worked example (a fair dramatization, not a memory replay of the quiz):

- **dashboard** — "AI-Assisted Drafting — Team Productivity" with speed-only
  metric cards: Drafts/day (▲30%), Avg draft time (▼), Queue cleared (%).
- **signals (hidden:true — the key)** — rework / correction rate; downstream
  error cost; net throughput; draft quality / accuracy. Each with a `why` tying
  back to the lesson (a speed metric drops quality, rework, downstream cost).
- **signals (hidden:false — decoys)** — drafts per day; average draft time
  (already on the dashboard; a `why` noting these ARE shown, so flagging them as
  "missing" misreads the dashboard).
- **intro** — frames the exercise: this dashboard looks great; name what a single
  speed number quietly leaves out.

Drafted by Claude for SME review.

## 7. Testing & verification (§4)

  - all hidden named, no decoys flagged → `correct = all hidden`, `missed = []`, `falseFlags = []`, `namedCount = hiddenTotal`.

  - a decoy flagged → that id in `falseFlags`.
  - empty selection → `missed = all hidden`, `correct = []`, `falseFlags = []`.
  - all signals selected → `correct = all hidden`, `falseFlags = all decoys`, `missed = []`.
  - bucket order matches config order.
