# P4.3a — "Error-seeding" Lab (cell 1.2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Design rationale + the full web-verified answer key live in `docs/superpowers/specs/2026-06-03-p4.3a-error-seeding-design.md`.

**Goal:** Add an auto-graded "spot the confabulation" exercise — `OutputAudit` — to cell 1.2. The learner reads a polished AI-drafted Housing Choice Voucher notice and audits it claim-by-claim (Supported vs Fabricated/unverifiable). Deterministic grading against an answer key (no LLM). Records a `lab_submission` but does NOT gate completion — the inline quiz stays the gate.

**Architecture:** Additive only. A new `OutputAuditConfig` member on the `LabConfig` union, a pure unit-tested grader (`outputAudit.grade.ts`), a self-contained `OutputAudit` component (renders artifact via `ReactMarkdown`, auto-grades on Submit, reveals per-claim `why`, records the submission, **no `onComplete`**), one `ModuleRenderer` dispatch case, and a content-as-data seed migration. Mirrors the P3.6/P3.7 pattern (`DataClassifier`/`FailureSpotter`). **No P4.2/P4.3b shared grading code is touched.**

**Tech Stack:** React 19 + Vite, TypeScript, Supabase Postgres migrations; Vitest for the pure grader + components; Playwright for the slice.
