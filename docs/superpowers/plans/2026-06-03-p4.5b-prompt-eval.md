# P4.5b — Reusable-prompt Eval Lab Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. See the design spec: `docs/superpowers/specs/2026-06-03-p4.5b-prompt-eval-design.md`.

**Goal:** Add an LLM-graded **reusable-prompt eval** on cell 2.10 ("Test-driven and constraint-first prompting"). The learner writes ONE constraint-first prompt, runs it live (`streamChat`) against a seeded test set (2 complete records + 1 edge case with a missing income field), then submits the prompt + its per-case outputs to the P4.2 judge for an anchor-scored verdict. Records a `lab_submission` but does NOT gate completion (the inline quiz stays the gate).

**Architecture:** A new `PromptEval` component (the shape — one prompt fanned out across N live runs → one multi-section grade — is genuinely new), but it **reuses every seam**: `streamChat` + `AbortController` cleanup (from `Lab`/`VoiceEdit`), `recordLabSubmission`/`saveGrade` (progress), `requestLlmGrade({brief, sections})` (the #48 judge), and `GradeResultCard` as-is. Add `PromptEvalConfig` to the `LabConfig` union, route it through `ModuleRenderer`, and seed the content as data via a migration. No `onComplete` (the inline quiz is the gate).

**Tech Stack:** React 19 + Vite, TypeScript, Supabase Postgres migrations; Vitest (jsdom for components); Playwright (chat + grade stubbed at the network layer).
