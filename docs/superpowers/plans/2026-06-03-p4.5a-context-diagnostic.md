# P4.5a — Context-window Diagnostic Lab Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. See the design spec: `docs/superpowers/specs/2026-06-03-p4.5a-context-diagnostic-design.md`.

**Goal:** Add an auto-graded, single-select **context-window diagnostic** on cell 2.5 ("Working with the context window"). The learner reads ~5 realistic civic-tech AI-session scenarios and picks the best diagnosis/remedy; auto-graded against a seeded `correctIndex`, with a per-item "why" and a keepable "Working with the context window — quick reference" takeaway. Records a `lab_submission` but does NOT gate completion (the inline quiz stays the gate).

**Architecture:** **Reuse the existing `ScenarioExercise`** component — this is the same single-select-scenario shape as 1.9 `disclosure-builder` / 1.10 `regulatory-check`. No new component. Add `'context-diagnostic'` to the `ScenarioExerciseConfig` `kind` union, add its `KIND_COPY` intro-card entry, route it through the existing `ScenarioExercise` dispatch group, and seed the content as data via a migration. The component's grade/takeaway/record logic is unchanged, so 1.9/1.10 stay byte-stable.

**Tech Stack:** React 19 + Vite, TypeScript, Supabase Postgres migrations; Vitest (jsdom for components); Playwright (auto-graded — no network stub needed).
