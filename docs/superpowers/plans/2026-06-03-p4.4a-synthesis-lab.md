# P4.4a — Synthesis Lab Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. See the design spec: `docs/superpowers/specs/2026-06-03-p4.4a-synthesis-lab-design.md`.

**Goal:** Add a `Synthesis` exercise (read sourced interview notes, write a synthesis that keeps the minority voice, graded in place by the P4.2/#48 LLM-judge) on cell 2.7 — graded practice that records a `lab_submission` but does NOT gate completion (the inline quiz stays the gate). Factor a shared `SourcedFreeTextLab` that both Critique (#48) and Synthesis use, keeping Critique byte-stable. No judge change (the `{brief, sections[]}` judge already fits).

**Architecture:** Mirror the #48 critique flow exactly (`recordLabSubmission`→id → `requestLlmGrade({rubric, submission:{brief, sections[]}})` → `saveGrade(id, result, 'reviewable')` → `GradeResultCard`; rendered above the quiz; no `onComplete`). The one structural move is DRY: extract `SourcedFreeTextLab` (Critique's body, generalized) and reduce Critique to a thin wrapper. Content is seeded as data via a migration.

**Tech Stack:** React 19 + Vite, TypeScript, Supabase Edge Functions (Deno), Postgres migrations; Vitest (jsdom for components); Playwright (`grade` stubbed at the network layer).
