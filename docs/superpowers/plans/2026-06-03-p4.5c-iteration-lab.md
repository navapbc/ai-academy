# P4.5c — Iteration-log Scorer Lab Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. See the design spec: `docs/superpowers/specs/2026-06-03-p4.5c-iteration-lab-design.md`.

**Goal:** Add an LLM-graded **multi-turn** exercise on cell 2.4 ("Iteration as the literate behavior"). The learner conducts a real multi-turn refinement conversation with Claude toward a constrained goal (a plain-language benefits **overpayment** notice), then submits the whole conversation; the P4.2 judge scores the **quality of the learner's iteration** (their steering turns), not the final output. Records a `lab_submission` but does NOT gate completion (the inline quiz stays the gate).

**Architecture:** A new `IterationLab` component — the multi-turn shape (an accumulating `messages[]` array sent to `streamChat` each turn + a minimum-turns gate) is genuinely new — but it **reuses every seam**: `streamChat` (which already takes `messages[]`) + `AbortController`/unmount cleanup (from `Lab`/`VoiceEdit`), `recordLabSubmission`/`saveGrade` (progress), `requestLlmGrade({brief, sections})` (the #48 judge), and `GradeResultCard` as-is. Add `IterationConfig` to the `LabConfig` union, route it through `ModuleRenderer`, and seed the content as data via a migration. No `onComplete` (the inline quiz is the gate). **Grading targets the learner's turns**, not the non-deterministic model output.

**Tech Stack:** React 19 + Vite, TypeScript, Supabase Postgres migrations; Vitest (jsdom for components); Playwright (chat + grade stubbed at the network layer).
