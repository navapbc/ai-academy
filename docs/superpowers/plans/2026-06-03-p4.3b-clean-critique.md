# P4.3b — Clean-critique Labs Implementation Plan

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. See the design spec: `docs/superpowers/specs/2026-06-03-p4.3b-clean-critique-design.md`.

**Goal:** Add a `Critique` exercise (read a polished AI artifact, write a critique, graded in place by the P4.2 LLM-judge) on cells 2.2 and 2.3 — graded practice that records a `lab_submission` but does NOT gate completion (the inline quiz stays the gate). The one shared-logic change is generalizing the judge's submission shape from `{brief,prompt,response}` to `{brief, sections[]}`, kept byte-equivalent for 2.1.

**Architecture:** Mirror the P3.6/P3.7 exercise pattern (component dispatched by `labConfig.kind`, renders above the quiz, no `onComplete`) and the P4.2 grading flow (`recordLabSubmission`→id → `requestLlmGrade` → `saveGrade(id,result,'reviewable')` → result card). The judge stays one function; only `GradeSubmission`'s shape generalizes. Content is seeded as data via a migration.

**Tech Stack:** React 19 + Vite, TypeScript, Supabase Edge Functions (Deno), Postgres migrations; Vitest (incl. the function's Deno-agnostic `verdict.ts`); Playwright (`grade` stubbed at the network layer).
