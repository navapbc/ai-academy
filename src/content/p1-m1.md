# Decoding the Black Box

Before you can use an AI responsibly, you need a working mental model of what it actually is — not magic, not a sentient brain, but a specific kind of mathematical system with well-understood strengths and well-understood failure modes. This module decodes the black box.

> **Key insight:** Every practical limitation of LLMs — hallucination, knowledge cutoff, context overflow — follows directly from how they are built. Once you understand the construction, the limitations stop being mysterious and start being manageable.

---

## What Is a Large Language Model?

A **Large Language Model (LLM)** is a neural network trained to predict the next token in a sequence of text. That's the entire mechanism. Everything else — the apparent reasoning, the code generation, the policy summaries — emerges from doing that one task at extraordinary scale on extraordinary amounts of data.

Training involves processing hundreds of billions of words from books, websites, academic papers, code repositories, and government documents. The network adjusts billions of internal parameters to get better and better at the next-token prediction task. When training finishes, those parameters are frozen. The model is a static artifact. It does not learn from your conversations unless it is explicitly retrained or fine-tuned.

### Tokens vs. Words

Models don't read words — they read **tokens**. A token is a chunk of text, roughly corresponding to about three-quarters of a word in English. The word "eligibility" is one token. The phrase "Hello, how are you?" is approximately six tokens. Common words are single tokens; rare or technical words may be split into multiple tokens.

This matters for two reasons:

1. **Cost and limits** are measured in tokens, not words. When a model has a "4,000 token context window," that's roughly 3,000 words.
2. **Tokenization affects behavior.** Models sometimes handle hyphenated terms, proper nouns, or non-English text differently because of how those strings are tokenized.

## Why LLMs Are Probabilistic

LLMs do not produce a single deterministic answer. They produce a **probability distribution** over all possible next tokens and then sample from it.

**Temperature** controls how that sampling behaves:
- At **temperature 0**, the model always picks the highest-probability token. Output is deterministic and conservative.
- At **higher temperatures** (0.7–1.0), the model samples more broadly. Output is more varied and creative — and more likely to go off the rails.

This is why asking the same question twice can produce different answers. It is also why "just ask the AI" is not a reliable QA process. The model is not looking up a fact; it is generating a statistically plausible continuation of your prompt.

```
# Example: same prompt, same model, different temperature

Prompt: "Summarize the key change in the 2024 Medicaid income limit."

Temperature 0:   Consistent, conservative, tends to hedge or refuse if uncertain
Temperature 0.8: More fluent, more confident-sounding — and more likely to fill gaps with plausible-sounding fabrications
```

## Hallucination: The Structural Problem

**Hallucination** is when a model produces output that is fluent, confident, and factually wrong. It is not a bug to be patched — it is an inherent consequence of the architecture.

Because the model is a next-token predictor, it will always generate *something* that sounds like a continuation of the input. It has no internal "I don't know" switch. If you ask about a Medicaid waiver that was passed after the model's training cutoff, it will not say "I have no information about that." It will generate a plausible-sounding description drawn from patterns in its training data about similar waivers.

Hallucination is especially dangerous in govtech contexts because:

- Policy details are often highly specific (exact dollar amounts, date ranges, eligibility thresholds)
- Users may not have the domain expertise to spot a plausible-sounding error
- A wrong answer about benefit eligibility has real material consequences for real people

The solution is not to avoid LLMs — it is to **ground** them.

## Context Windows

A **context window** is the maximum amount of text (measured in tokens) that a model can "see" at one time. Everything outside the context window is invisible to the model.

Common sizes as of 2024–2025:

| Model class | Approximate context window |
|---|---|
| Small/fast models (Llama 3.2 3B) | 4,000 – 8,000 tokens |
| Mid-range models (Mistral 7B) | 32,000 tokens |
| Large local models (Llama 3.1 70B) | 128,000 tokens |
| Commercial frontier models | 128,000 – 200,000 tokens |

This matters practically because:

- A 100-page policy document is roughly 75,000 words, or ~100,000 tokens. It may not fit in a smaller model's context.
- Even when content fits, models tend to attend more closely to the beginning and end of the context window. Important content buried in the middle may be underweighted.
- Every message in a conversation consumes context. Long chat threads can crowd out the grounding documents you carefully injected.

## Knowledge Cutoff

Every LLM has a **training cutoff** — a date after which it has seen no data. A model with a January 2024 cutoff does not know about a Medicaid policy change from March 2024. It does not know about a new state eligibility rule published last month. It does not know what happened yesterday.

This is not a solvable problem through prompting. You cannot ask the model to "update itself." The only solutions are:

1. **Grounding** — inject the current policy text into the context window at query time
2. **Fine-tuning** — expensive and slow, typically reserved for significant domain adaptation
3. **Tool use / retrieval** — give the model access to a live document database (covered in Phase 2)

For Nava work, assumption one is the default. Always treat the model's built-in knowledge of policy details as a draft to verify, not a source of record.

## The AI Harness

A raw LLM with no constraints is like a powerful engine without a steering wheel or brakes. The **AI Harness** is the software architecture that makes a raw model safe, useful, and aligned with a specific deployment context.

The harness has four components:

### 1. System Prompt (Identity)
The system prompt is a hidden instruction block sent to the model before every conversation. It defines the model's persona, scope, and constraints.

```
Example system prompt:
"You are a benefits navigator assistant for a state Medicaid program. 
You only answer questions using the policy documents provided below. 
If a question falls outside those documents, say 'I don't have 
information about that in my current policy set' — do not speculate."
```

### 2. Grounding (Truth Source)
Grounding means injecting authoritative reference material — a policy PDF, a regulatory excerpt, a data schema — directly into the prompt. The model is instructed to base its answer only on that material. This is the primary defense against hallucination.

### 3. Guardrails (Safety Filters)
Guardrails are checks applied to inputs and outputs. Input guardrails can detect and block PII before it reaches the model. Output guardrails can flag responses that contain specific patterns (e.g., a model that starts generating a real SSN format). These can be rule-based or themselves AI-powered.

### 4. Validation (Output Checking)
A second model — often smaller and faster — scores the primary model's output for factual consistency with the grounding documents. If the score falls below a threshold, the response is flagged or rejected. This is sometimes called **LLM-as-judge**.

## Ungrounded vs. Grounded: A Concrete Example

**Scenario:** You need to know the current income limit for a childless adult on your state's Medicaid expansion plan.

**Ungrounded query:**
> "What is the Medicaid income limit for a single adult with no children in my state?"

The model answers from training data. That data may be 18 months old, may reflect a different state's rules, or may interpolate incorrectly between several states' policies. The answer sounds authoritative.

**Grounded query:**
> "Using only the policy excerpt below, what is the current income limit for a childless adult? [STATE MEDICAID POLICY DOCUMENT TEXT]"

The model is constrained to the document you provided. If the document is current and accurate, the answer will be current and accurate. If the document doesn't contain the answer, a well-constructed system prompt will cause the model to say so rather than speculate.

> **Takeaway:** Grounding is not optional polish — it is the mechanism that makes LLMs usable in high-stakes govtech work. Every practical exercise in this course will reinforce this habit.

## Key Terms Recap

| Term | Definition |
|---|---|
| **LLM** | Large Language Model; a neural network trained on text to predict the next token |
| **Token** | The unit LLMs process; roughly 3/4 of an English word |
| **Temperature** | Controls randomness in token sampling; 0 = deterministic, 1+ = highly varied |
| **Hallucination** | Confident, fluent, factually incorrect model output |
| **Context window** | The maximum token capacity a model can process in one turn |
| **Knowledge cutoff** | The date after which the model has no training data |
| **Grounding** | Injecting authoritative reference material into the prompt |
| **AI Harness** | The software layer (system prompt, grounding, guardrails, validation) that constrains a raw model |
